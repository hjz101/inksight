# 技术约束清单 · 墨见 InkSight（给架构/工程）

v1.5｜摘自 PRD v2.10，并含台账 D-52 的架构侧同步（新增 NFR-09 后台重分页正文不常驻、NFR-10 动效开关单一真相与可关集合、NFR-11 协调器单例化与后台重排可中断、NFR-12 动效实现目录与触发纪律、NFR-13 容器尺寸单一来源与单例由构造保证）；只列**不可妥协项**。凡标 Blocker 的，不达标即阻塞发布。

## 一、排版与渲染

**FR-031 排版唯一来源（Blocker）**
- 渲染输入只有一种：`[Paragraph]`（type: text / image / title）结构化数据 ＋ `ReaderTypography` 单一排版来源。
- 渲染层**不得接收 AttributedString，不得含任何 HTML**。
- 零位移靠**自绘断行**：`CTTypesetterCreateLine` 只接受我方 range，禁则表＋逐字 advance 累加决定断点与标点宽度；显式关 `palt`/`halt` 兜底。
- **前置条件：字体白名单（内置字体）**。不成立则「跨源零位移」在物理上不成立，只能降级为「同字体零位移」。
- 验收 AC-1：喂 `<p style="font-size:20px;text-indent:2em">`，断言 `sourceStyleResidual == 0`。
- 观测 AC-2：`strippedStyleCount > 0` 只进调试面板，**不设阈值、不进验收**。
- POC-3 判定：标点密集样本上 `CTLineGetTypographicBounds` 与自绘累加 advance 之差 **>0.5pt 判不可行**。

**`TypographySignature`（缺一项都会出事）**
`hash(fontID, fontSize, lineHeightMultiplier, paragraphSpacingBefore, paragraphSpacingAfter, insets×4, indent, imagePlaceholderAspect, containerSize, screenScale, 禁则表版本号)`
禁则表版本必须入签名——表一变断点就变，不入签名会让旧 anchor 永久复用错页，且只能靠重装 App 才"修好"。
重分页：签名变化 → 同步作废全部缓存（O(1)）→ 当前章同步重排（15–30ms）→ 其余章后台分批（1 章/次）。

**NFR-09 后台重分页正文不常驻（新增，D-52 架构侧同步）**
FR-031 的「其余章后台分批（1 章/次）」与 NFR-08 的「分页只做当前章＋前后各 1 章／预取仅内存 ≤3 章／遍历全书生成 anchor 视为违规」并存，靠两条实现纪律同时成立：
- **① 每批只处理 1 章**：后台重分页单章出队、单章重排、单章落锚点，不做全书一次性遍历。
- **② 队列只存取正文的闭包，不存正文**：处理到哪一章才切片读哪一章（正文按需读取），读完即释放——**任意时刻常驻正文 ≤1 章**。
判据：任何「先把全书正文装进内存、再逐章分页」的实现视为违规（等价于把 NFR-08 禁止的遍历搬进内存，同时破 NFR-03「会话正文本 ≤50KB／≤3 章」）。生产路径须用「按需取正文」的入队接口；「正文已在调用方内存」的便捷入口仅限正文本已在内存且 ≤3 章的短时场景。
出处：开发包 #6 实现「TypographySignature 变更 → 缓存作废 → 当前章同步重排＋其余章后台分批」机制链路时暴露；架构侧裁定「后台批处理」与「正文不常驻」并存，列此条以免该纪律在后续包回退。

**NFR-11 协调器单例化与后台重排可中断（新增，D-52 架构侧同步）**
- **分页协调器必须 App 级单例**：`TypographySignature` 全局可比，但 `PageAnchorCache` / `CTFrameCache` 挂在**协调器实例**上——两个实例＝两套缓存＝同一本书在设置页与阅读器各排一遍、缓存互不命中（白排一遍），且 NFR-03 的内存预算按实例翻倍。判据：设置页与阅读器必须共用同一协调器实例；测试用独立实例以避免跨用例污染。
- **换排版后落点靠 `charOffset` 重新二分**：重排前后落点用**同一 `charOffset`** 表达，新页索引由 `charOffset` 经**新锚点**二分得到，误差 ≤1 屏（定位铁律在重排场景的延伸）。**重排不得把 `pageIndex` 写进任何持久化模型**——换排版不豁免定位铁律。
- **后台重分页必须可中断**：`cancel()` 后立即停止处理下一章（已在处理的那一章跑完即止）；`scenePhase != .active` 立即停（对齐 NFR-04 纪律精神）。判据：任何「不可中断的后台批量重排」视为违规——用户切走或换书时它仍在跑。
出处：开发包 #8 把重分页机制回接真实阅读链路、并让后台调度真实驱动时暴露；架构侧裁定「协调器单例」「重排后靠 charOffset 重新定位」「后台重排可中断」三条，列此条以免后续包回退。

**NFR-13 容器尺寸单一来源与单例由构造保证（新增，D-52 架构侧同步）**
- **容器尺寸必须只有一个来源**：`TypographySignature` 含 `containerSize`——设置页与阅读器若用不同尺寸，签名就不同，即使共用同一协调器（NFR-11）两端缓存也**互不命中**（同一本书排两遍、白排一遍）。判据：阅读器实测后回报真实尺寸，设置页与阅读器**从同一来源读取** ⇒ 两端签名必然一致 ⇒ 缓存真正互通；**不得为此引入第二套尺寸常量**（种子值取既有 `ReaderEngine.defaultContainerSize`，之后一律由实测值覆盖）。
- **单例必须由构造保证**：默认参数**即** App 级单例，不靠「记得传 `.shared`」——漏传一次就静默退化成第二个真相，且无任何测试能捕捉（与 NFR-10 同型风险）。判据：默认构造得到的对象**就是** App 级单例；需要隔离（单测）时**显式**传独立实例。
出处：开发包 #10 实施「容器尺寸贯通」与「单例由构造保证」时暴露；架构侧裁定「尺寸单一来源」「单例由构造保证」两条，列此条以免后续包回退。

**定位铁律**：任何持久化存储**不得以 `pageIndex` 作定位依据**，一律存 `charOffset + fingerprint`。`pageIndex` 只作 UI 快速显示 hint，签名不匹配即丢弃重算。改字号/边距即触发重排，存页码会当场跳页。

**FR-008 五种翻页（摘要）**：仿真/覆盖/滚动/上下/无动画，帧率受 NFR-02 约束；仿真翻页期间玻璃浮层必须收起或转不透明。

**FR-011 进度与书签（摘要）**：进度存到「章节＋字符偏移」，杀进程后恢复误差 ≤1 屏；进度以偏移为准、**不以页码为准**（跨设备边距差异会导致页码不同）。

## 二、性能（Blocker）

**NFR-01 冷启动（双指标，不合并）**：首帧 ≤800ms；首屏可交互 ≤1.2s。

**NFR-08 分页缓存纪律**：`ChapterPaginationCache` key=`(chapterId, signature)`，**`PageAnchor` LRU 10 章**（架构 v1.9 勘误，台账 D-52；PageAnchor 非正文，不受"会话内存 ≤3 章"约束）；**`CTFrame` 按页 LRU 7 页（当前 ±3）**；**任何"遍历全书生成 anchor"的代码视为违规**（同时破内存与合规"预取仅内存 ≤3 章"）。目录（分章）只产 `(offset, byteLength)` 不解析正文；分页只做当前章＋前后各 1 章。20MB 首开：分章索引 40–80ms ＋ 首章分页，峰值预算约 90MB。

**NFR-02 翻页帧率**：59fps+，ProMotion 设备 118fps+，掉帧率 <1%，单帧 P95 ≤16.7ms。
前提：翻页期玻璃收起/不透明；仿真翻页的页位图不得与 backdrop 逐帧重算争 GPU。

**NFR-03 内存**：常驻 ≤300MB，开 20MB txt ≤400MB，无 OOM。预算：页位图 ≤10MB（降采样，仅当前页＋相邻 2 页）、`CTFrame` **≤1MB（按页 LRU 7 页，当前 ±3；实测约 420KB——v1.0 的 8MB 为拍脑袋值，已由架构 v1.9 勘误，台账 D-52）**、会话正文本 ≤50KB（≤3 章）、SQLite cache 8MB。位图只在仿真翻页时物化。

**NFR-06 功耗温控**：连读 30 分钟掉电 ≤5%、温升 ≤4℃（25℃）、不触发系统降亮度。
前提（指标是架构换来的，不是调优出来的）：阅读页 0 玻璃、静止 3s 停 `CADisplayLink`、`preferredFrameRateRange` 仅动画期 118–120、不做逐帧自绘玻璃。

**NFR-04 并发**：`min(6, 启用源数)`，单源超时 8s，**首屏增量回调：6s 起持续返回（实现策略，不作 Blocker）；整体硬上限：10s 到点即返回已到结果（Blocker 判据）**；`scenePhase != .active` 立即 `cancelAllTasks()`；`BGTaskScheduler` 不注册抓取任务（同时是未成年人模式断网的实现基础）。

## 三、合规派生硬约束（不可协商）

**FR-024a 本地全文检索**：索引对象仅本地导入文件；FTS 库设 `NSURLIsExcludedFromBackupKey`；万本级首屏 ≤1s。
**FR-024b 在线进度映射**：只存章节号／标题／字符偏移／首尾指纹哈希，**表结构里没有正文字段**，FTS 不索引在线正文；检索范围＝本地 FTS ＋ 会话内存已加载章节（≤3 章），会话结束即销毁。**代价明确：在线书不支持跨会话全文检索。**
**缓存目录**：`Library/Caches/InkSight/{Pages,Images}`、`Application Support/InkSight/FTS` 全部设 `NSURLIsExcludedFromBackupKey`；会话结束或一键清除即销毁。
**FR-025 导出**：显式排除在线正文，只含本地文件、进度、笔记。

## 四、动效

**FR-030**：13 个 ID 必须登记（T1–T6、EGG1–EGG5、UIT1、UIT2），未登记构建失败；`MotionCoordinator` 为唯一入口。
**全局总关＝不播动画路径，不是时长设 0**：`withTransaction(Transaction(animation: nil))` ＋ `AnyTransition.identity` ＋ 彩蛋不创建视图。验收为**首帧末帧逐帧 diff 为 0 且无中间帧**（截帧验证）。
可关 11 个；T4 直切回位＋位置标签，T5 降级 0ms 静态成功态——**反馈必须留，动画不必播**。
可关转场禁用系统 push / sheet morph。

**NFR-10 动效开关的单一真相与可关集合（新增，D-52 架构侧同步）**
- **运行时唯一真相＝`MotionCoordinator`**（FR-030 唯一动画入口）。持久化文件只是它的**镜像**：变更即时落盘、启动时回灌。判据：任何「绕过 `MotionCoordinator`、直接读持久化文件决定播不播」的实现视为违规——会产生第二真相，设置与实际播放不一致。
- **可关集合＝11 个**（T1／T2／T3／T6／EGG1–EGG5／UIT1／UIT2）；**T4／T5 无独立开关**（FR-030 明文）。
  注意与 A 档 `closable` 区分：`closable`＝「关掉时走不播动画路径」这一**档位**（13 个全为 true），**不等于**「给用户一个独立开关行」——两者不得混用。
- 该集合与分组归属（转场 4／彩蛋 5／手势 2）**必须由穷举 switch 派生**：新增 `MotionID` case 未登记即**编译失败**（同 FR-030「未登记构建失败」纪律），避免 UI 与枚举静默脱钩。
- **总关优先级最高**：判定式为「全局总关 AND 未被单独关闭」——任何单 ID 开关都不能绕过总关；且「不播动画路径」须**逐 ID** 生效，单关某 ID 不得牵连其余 ID。
- 动效开关属**用户偏好 → 可备份**（不设 `NSURLIsExcludedFromBackupKey`）。

**NFR-12 动效实现目录、触发纪律与减弱动态效果（新增，D-52 架构侧同步）**
- **实现目录必须由穷举 switch 派生**：13 个 ID 一条实现描述，**一个不多一个不少**；新增 `MotionID` case 未登记即**编译失败**（同 FR-030 纪律，避免目录与枚举静默脱钩）。每条须登记：开态视觉、关态降级方式、是否有独立开关、注册模式、年龄态注册条件、**自然触发位置**（DESIGN §4.1 单一来源）。
- **触发点只调 `MotionCoordinator.perform(_:_:)`**，不得自己读设置文件、不得自己判断播不播（NFR-10 的延伸）。
- **动效期间禁止插值材质参数**（tint/blur/refraction）——只允许插值 opacity 与 transform。判据：纪律**写进类型**（描述符字段恒为 false）＋**源码扫描**双重守卫；材质一变即触发 backdrop 全屏重算（四层叠加），**T3 最易犯**。
- **系统「减弱动态效果」优先级最高**，且**只去动画、不去功能**——触发照常执行、状态变更照常生效，只是不播动画路径。这与「用户总关」下 `dropTrigger` 连触发一起短路的语义**不同**，**不得混为一谈**（前者是系统无障碍，后者是用户主动不要该功能）。
- **彩蛋的注册与限流是同一条开关**：关态时限流器**一并停跑**，且**不消耗限流额度**（否则用户关掉动效期间会白扣次数，重新打开后第一次触发就被挡掉）。
出处：开发包 #9／#10 把 13 个动效实现为真实可播效果并接线真实触发点时暴露；架构侧裁定四条，列此条以免后续包回退。
