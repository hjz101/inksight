## 1. 定位与用户

**价值主张**：书源会烂，但阅读不该中断——换源之后，你仍在同一页。**定位**：不追更大的书库，做**书架与书源的治理层**，把测源、核章、调排版的心力税收成一次点击。

**人物 A｜林亦然，24 岁，运营**。iPhone 15，地铁 40 分钟＋睡前 25 分钟；听书与碎片阅读，囤 200+ 本。要接着读、要记得住，最恨假装有内容。

**人物 B｜陈墨，27 岁，后端**。iPhone 17 Pro，Legado 迁移者，囤 40+ 源每周测源。要换源不丢位置、排版不变形；翻页零卡顿。

## 2. 功能清单

P0 首版必做｜P1 二期｜P2 观察；AC＝验收标准（可测）。

**术语红线（内部名 vs UI 文案必须分开）**：本 PRD 内「换源／书源／多源／订阅源／源站」属**内部研究术语，一律不得进入 UI**——UI 用「**切换文件／切换版本**」（这句话读起来像"我们在操作多个来源"，正是要防的自认；**技术标识符如 `SourceEngine` 可保留，但不得出现在用户可见字符串/日志/遥测/崩溃报告/导出文件**，也不得有 `SourceMarket` 之类描述"我们不做的事"的空壳标识符）。
**动作词规则（终版，一句话）**：**`.minorConfirmed` 内不出现「导入」**（功能在该态确实不存在）；**其余全部态统一用「导入」**（"导入你的书"是 B 版核心定位词）。**两名制已作废**——受限三态里两个态本就允许导入，按"受限与否"分叫法会制造"同一功能两种词"的不一致。**边界不是"受限与否"，而是"功能在不在"：功能在的地方就叫原名。** 见 §12。「**联网**」不得用于"联网找书/联网获取内容"，"设备联网后""网络可用时"属设备状态描述，允许。「更新／追更」不入 UI 主链路。
**分域提醒**：本 PRD 与技术约束清单属内部件，可用术语红线兜住；**交付文档、对外部分、会随交付物流出的章节必须逐处真改"换源"**——判据是"会被整份调取的东西，不能靠内部约定兜"。
**判定依据**：《禁词与文案合规检查表》（`deliverables/禁词与文案合规检查表-墨见InkSight.md`）§1 七条判据——清单会过时，判据不会；拿不准按"是"处理。
**`[待合规确认]` 制度**：凡结论跨越"许可/合规边界"，一律加 `[待合规确认]`，在合规侧书面回应前不得视为默认生效。这类结论的失效方式特别隐蔽——技术可行、评审无人反对，后续版本就当既定事实引用。**摘标也要留痕：谁、何时、基于哪条书面回应摘的**（"什么时候被确认的"和"确认了什么"同样重要）。
**已归档（2026-10-27 合规书面确认，可摘标）**：①宵禁/时长适用范围 ②`CTFrame` 视同正文不落盘（含不进崩溃快照与内存转储）③代码标识符可保留技术词（边界：不得进用户可见字符串/日志/遥测/崩溃报告/导出文件，不得有描述"我们不做的事"的空壳标识符）④字体按名称引用＋OFL 随包附许可。
**摘标留痕并入 §11 改判记录（不另立台账——两套记录必然分叉，只会有人更新其中一个）**：每条摘标写清「哪个 `[待合规确认]`、何时、基于哪份书面结论」。
**空壳标识符判据（两问法）**：第一道——①只读这个名字（不看代码），会以为这个 App 能做什么？②那个能力现在存在吗？②为"不存在"→名字必须改或删（它描述的不是代码现状而是产品意图，而意图会被当证据）。第二道才是可达性筛：**过不了第一道的，说明它本来就不该有名字；过了第一道但不可达的，那是死代码，删掉。**

**正文样式基线（FR-031 截图 diff 基准，开发按此写死）**

| 项 | 基线值 |
|---|---|
| 字号 | 19 / **20（默认）** / 21 pt |
| 行高 | 倍数 1.70 / **1.75** / 1.85；行盒 `minimumLineHeight = maximumLineHeight = 字号×倍数`（20pt→35pt）**（行盒唯一真源，见台账 D-31）** |
| 段间距 | 12pt（0.6em）；连续空段折叠为 1，不叠加。**段间视觉间距 = 12pt，不由行盒余量叠加**（段前 12、段后 0）；**页首段落 `paragraphSpacingBefore = 0`**，否则每页首段下移 12pt |
| 首行缩进 | **0pt（默认）**；开启时 = 2×字号（20pt→40pt） |
| 边距 | 档位 16/20/24pt；**首次启动按屏宽定默认**：≤375pt→16、>375pt→20，此后旋转/尺寸变化**不再重算**；**用户改过即永久锁用户值**。上 = 导航栏底 +24pt；下 = 28pt + 安全区 |
| 字重 | 正文 PingFang SC **Regular 400**；章标题 22pt Semibold；书名 17pt Semibold；UI 15pt Regular |
| 对齐 | 左对齐（natural）；**不做两端对齐**（中文两端对齐拉大词距，长读疲劳） |
| 标点 | 全角；断行与标点宽度由**自绘禁则表＋固定 advance** 决定，不依赖系统 `punctuationProcessing`（iOS 无此开关） |
| 图片 | 宽＝正文宽，占位比例 `imagePlaceholderAspect` **默认 3:4**（并入 `ReaderTypography`），aspect-fill；长图点击进全屏原图；图注 11pt 居中、上下各 8pt；图与段间 16pt |

**`TypographySignature` 定义（缺一项都会出事）**：`hash(fontID, fontSize, lineHeightMultiplier, paragraphSpacingBefore, paragraphSpacingAfter, insets×4, indent, imagePlaceholderAspect, containerSize, screenScale, 禁则表版本号)`。禁则表版本必须入签名——表一变断点就变，不入签名会让旧 anchor 永久复用错页，且**只能靠重装 App 才"修好"**。
**重分页策略**：签名变化 → 同步作废全部缓存（O(1)）→ 当前章同步重排（15–30ms）→ 其余章后台分批（一次 1 章，让出 CPU）。
| 剔除清单 | 源方内联 style、class、font-family、color、text-indent、letter-spacing、加粗斜体、自定义字号，清洗阶段全剥；验收看 `sourceStyleResidual == 0`（`strippedStyleCount` 仅作观测，不设阈值） |

**一句话给开发**：正文渲染属性只由本地配置决定，源只提供「段落文本＋图片 URL」两种东西。

**防复发注记**：**字体白名单＝名称白名单。禁止把"随包分发"写成确定性的必要条件**（苹方/SF Mono 系 Apple 系统字体，"经系统 API 使用"是授权、"随包再分发"不是）。

三条理由：①"未完善"指向用户可做的动作，"未确认"只陈述我们没拿到；②**限制类文案要给动作，不给时间点、也不给"系统会自动确认"这类被动承诺**；③"未成年人保护已生效"是**该态套宵禁的正当性支点**，少了它宵禁就成了没有解释的限制（用户当 bug）。另："继续使用"→"**继续阅读**"——限制类文案要说清限制的是哪个动作，"继续使用"会被读成"使用 App"。
**允许导入的闭环（没有它，允许导入就是漏洞）**：`.ageUnresolved` 后来收敛为确定未成年时，走「家长内容确认流程」——列出这段时间新增的 N 本，选全部保留／仅保留指定，把内容补审一遍。**闭环不是"事前禁"，是"事后补审"**——这正是它能同时拿到可用性与把关的原因。
**可达性定稿（否则"允许导入"就是纸面权利）**：**拦截页 ≠ 该态的主界面**。`.ageUnresolved` 平时正常可用——书架可看、可读、**可导入**，只是顶部常驻 28pt 状态条；**拦截页只在宵禁时段（22:00–6:00）全屏替代主界面**，此时无任何入口，这是时段限制的本意、不是可达性缺陷。入口位置（非宵禁时段）：书架空态主按钮「导入你的书」、书架工具栏「+」；**状态条不遮挡、不拦截、不吸底，不得做成覆盖式横幅**。
**四条验收项**：①非宵禁时段「导入你的书」与「+」可见可点，能完成导入并出现在书架；②宵禁时段拦截页全屏且**此时不存在任何导入入口**（不是隐藏、不是变灰，是不存在）；③状态条存在时书架首屏可用高度减少 **≤28pt**；④重试成功 → 宵禁立即解除、拦截页当场消失、回到原界面（含导入后的书架）。

| `.ageUnresolved` | 「年龄信息未完善 · 未成年人保护已生效」 | 同 || `.unverified` | 「**年龄信息未完善**」（常驻提示，不写任何限制声明） | 「年龄信息未完善：在线功能不可用」〔台账 D-02〕 |

**理由：不得声明不存在的限制**——B 版发行版里没有"在线功能"可被禁用，写这句会让用户以为我们本来有在线内容能力，正撞自己的对外声明。**声明一个不存在的限制，与声明不存在的内容同为虚假陈述，只是方向相反。**
**视图层不得各自拼文案**：三态状态条必须从**二维矩阵**派生；视图自己拼一定被拍平成一维（本轮"按钮取消"就是矩阵改了、判据没跟上）。
**UI 三态条（从矩阵派生）**：`.minorConfirmed`＝「未成年人模式」；`.ageUnresolved`＝「**年龄信息未完善 · 未成年人保护已生效**」＋caption（见下）；`.unverified`＝「年龄信息未完善：在线功能不可用」。三态不得合并显示。——`openSettingsURLString` 只到本 App 设置页（我们没有 settings bundle 项，用户会点进空白页，比没按钮更糟），deep-link 到系统「App 年龄段」无公开 scheme。它长得像可点就破了。

**FR-032 能力边界（判定口径：功能是否可被豁免）**
- 模式内「永不可用」能力（书源、搜索、导入、全部网络访问）**不在任何层级出现**，不设禁用态、不设灰、不设"升级/验证解锁"提示。理由：禁用态这种 UI 语言暗示"有朝一日会开"，而它们没有豁免路径，属于承诺一个不存在的未来。
- 模式内「家长可配置」项（每日时长、可用时段、可读书目筛选）在**家长设置**内以控件呈现。
- 「我」页设独立分组「**关于本模式**」（不用"模式说明"——"设置"会被孩子读成"这里能改"），文案：「本模式下，本机已导入的图书可以正常阅读，进度、笔记、排版设置均可使用。每日可用时长与时段由家长设定。」
- **AC（可测）**：该分组文案内**不得出现**以下词：书源、搜索、导入、联网、"限制"、监护验证后可切换、任何解锁路径提示。解释"被禁止了什么"是剥夺叙事，列举"你有什么"是赋能叙事。

**合规硬约束**：端侧仅保留会话内渲染所需内存页与预取章节（≤3 章），会话结束或一键清除即销毁；缓存与索引目录必须设 `NSURLIsExcludedFromBackupKey`，不参与 iCloud/iTunes 备份。
**`CTFrame` 视同正文·四条（已合规书面归档）**：判据是"是否形成稳定可再现的副本"，数据类型不是——`CTFrame` 底层承载字符串，持久化后与正文缓存性质相同。①仅在内存持有，切书或会话结束即释放；②**不写入任何磁盘路径**（含 `Caches/`、`tmp/`、`Application Support/`）；③**不进崩溃快照，含 `MetricKit` 的 `diagnostic` 包**；④**不进内存转储文件**。③最容易被"为排障好"绕过——**理由充分、无人反对、无声违规**。
**代码标识符边界（已归档）**：`SourceEngine`／`SourceRule`／`ImportService` 可保留（禁词表管的是"对用户与公众的表述"）；但①不得出现在用户可见字符串、日志、遥测、崩溃报告、导出文件；②不得出现在交付文档的对外部分；③**不得有描述"我们不做的事"的空壳标识符**（`SourceMarket`／`RuleHub`／`SubscriptionFeed` 即使从未调用，也是"我们曾计划做"的证据）。
**日志与遥测红线**：不得记录第三方域名、站点名、书源标识，**哈希也不行**——判断标准是**输入熵**而非"是否哈希"：域名低熵、彩虹表可反查，哈希等于明文；段落指纹输入是数百字高熵文本，可存哈希。书源在日志中只允许 `sourceSlotIndex`（本地序号）或不记。

## 4. 核心主流程（文字流程图）

1. **导入**：复制源链接 → 「我-书源」粘贴 → 解析 JSON → 校验（必填字段＋示例搜索）→ 入库给健康度；失败指出不合法规则。
2. **搜索**：先查本地库（命中直接开书）→ 未命中并发 8 源 → 去重排序 → 结果标源名与已缓存章节数。
3. **换源**：用户手动在结果中选另一源 → 校验有无当前章节 → 命中即做指纹对齐 → 剔除源样式套本地排版 → 提示「已对齐至第 12 章同一段」；**不自动搜源、不拼接多源章节**。
4. **阅读**：读设置 → 预取后 3 章（仅内存，不落盘）→ 翻页写进度（章节＋偏移）→ 空闲落库。
5. **进度同步**：写本地 → 有网推 iCloud（时间戳比对，仅进度与笔记）→ 他端拉取提示「接续到另一台设备的位置」。
6. **离线可读**：仅对本地导入文件生效（txt/epub 入库即本地）；在线内容不下载、不缓存；断网时架上标「本地可读」直读文件。

2. **「授权」二字在无授权文件时一个都不能写**（含"正版授权""已获授权""授权内容"）——虚假宣传＋版权争议加重情节，比"精校版"重得多。**例外**：§10 用户责任条款中"用户应确保已获授权"是对用户的义务陈述，保留。
3. **凡"我方替用户宣称内容更好/更全"的词一律禁**：全本／全集／完结版／补全／完整版／精校／精校全本；「净化」改为「排版清理」；主链路禁「更新/追更」。
**禁语清单**：聚合/搜索全网内容、支持××书源、**支持导入书源规则**、永久免费/无障碍阅读、某平台独家作品可读、「本应用不存储任何内容，内容均来自第三方」（反向自证）。

4. 每次编辑后**搜一遍被本次编辑触及的编号**，确认没有跨条合并（本轮曾一次编辑把 FR-032 与 FR-033 拼成一行）。
5. 本节与 §11 改判记录不可省——`旧结论不会自己消失，它会以"改良版"身份回来`。

旧结论不会自己消失，它会以"改良版"身份回来，而没人记得为什么否过。以下每条都带否决理由，重提时先读理由。

三条边界：①全部**无按钮**、无"退出/解锁/切换/跳过"；②副文案**只陈述规则、不做倒计时**（禁"还剩 X 小时""将于 X 点恢复"——时间锚点会造成设闹钟、到点冲进来读，与防沉迷目的反向）；③**`.minorConfirmed` 无系统路径**（该态由家长在系统侧控制，给路径等于暗示用户可自行改变状态）。
**⚠ 差异必须保留，勿"统一"**：「未成年人保护已生效」**只出现在 `.ageUnresolved`**，不出现在 `.minorConfirmed`。理由：前者**不确定是否未成年**，必须显式声明宵禁的正当性支点；后者页首词就是「未成年人模式」，**模式名本身即带义务**。**不写理由，下一个人会当成两页不一致去统一，然后把 `.ageUnresolved` 那句删掉——那等于删掉论证支点。**

**✅ caption 冲突已裁定（第四版作废）**：定稿「**年龄信息未完善 · 未成年人保护已生效，完善后即可继续阅读**」。作废的 A 版「…完善后即可**继续使用**」有两处差异，都不是字数问题：①**缺「未成年人保护已生效」＝宵禁没有解释**——用户 22 点被拦住会问"为什么现在不能读"，而"标签自带义务"这条论证的支点在界面上就不存在；②「继续使用」泛指，会被读成"使用 App"，而我们拦的是阅读——**限制类文案要说清限制的是哪个动作**。

## 15. 原型层验收口径（本期在原型层完成验收〔台账 D-04〕）

原型维持高保真，13 个动效与三态在本期验收。以下判据**在原型层即可判定**，不依赖真机。

| 项 | 判据 | 口径 |
|---|---|---|
| **动效挂载数** | 13 个 ID（`T1`–`T6`、`EGG1`–`EGG5`、`UIT1`–`UIT2`）**逐一在原型中可触发**，计数须为 **13/13**；未挂载或 ID 不匹配即不通过 | 逐个触发并记录，**附截图或触达路径** |
| **减弱动效实测值** | 开启"减弱动效/全局总关"后，全部动效的 `transition-duration` 实测为 **0.001s**（或等效零时长），**且首帧与末帧逐帧 diff 为 0、无中间帧** | 取实测值而非代码声明值；**不得用 `duration == 0` 断言代替**。**帧级判定二选一**：浏览器自动化逐帧比对 **或** 人工录屏；**录屏须作为证据留存**——静态核机制在位只能判"机制在位、帧级待实测"，**不得虚报通过** |
| **`∅` 结构不生成** | `∅` 单元格对应节点**在 DOM 中不存在**（不是不可见）：`.unverified` 下"预览宵禁拦截页"按钮不存在、`.adultConfirmed` 下我页该行右侧说明为空 | 用「DOM 中不存在该节点」判，**不用**「节点不可见」判 |
