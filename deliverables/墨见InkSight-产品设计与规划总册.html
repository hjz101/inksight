⚠ 风险前置：本方案「仅作产品研究与技术预研，不用于实际发行」

本方案按你的要求，完整保留了「聚合书源 + 用户导入」形态。但必须把话说明白：该形态在中国现行法律框架下被判定为阻断级风险，不可用于实际发行，理由集中在三点——

1. 司法采「用户感知标准」。只要用户在 App 内读到统一排版、无跳转、无来源标识的内容，法院就认定是「你的 App 在提供作品」，"内容不在我服务器"不构成免责。

2. 分发针对性抓取规则＝技术支持型帮助侵权。再叠加书源市场、聚合搜索、榜单推荐、广告变现，构成要件即齐全。国内已有书源类 App 开发者以侵犯著作权罪获有罪判决，定罪核心恰是「编写抓取规则 + 系统聚合 + 社群推荐 + 营利」。

3. 渠道层面直接堵死。App Store 指南 5.2.3 禁止协助非法文件共享、提供保存/转换/下载第三方媒体的能力；2.5.19 禁止审核期隐藏功能（后果是下架并封开发者账号）。国内安卓渠道对「图书阅读类」硬性要求网络出版服务许可证或内容合作证明。

因此本册全部内容应被理解为产品形态研究、交互与视觉验证、以及技术预研。第 9 章给出了可发行的收敛路径（本地精读器 / 正版化）。

00一页读懂

一句话定义：一个把「找书、读书、记住」三件事重新做一遍的阅读器——内容靠用户自己带来，产品只负责把"读"这件事做到极致。

目标用户

18–30 岁、日均阅读 40 分钟以上

深夜床上读、通勤读、蹲坑读。手机就是书房。接受自己找书源，但不想当运维。

核心矛盾

精力花在维护工具，而不是读书

书源腐烂、章节缺失、切换版本即排版崩坏——用户沦为"技术维护工"，这是聚合类产品的原罪。

差异化 1

液态玻璃，但克制

玻璃只上浮层，正文区永远干净。一屏最多 1–2 处。堆满玻璃连读 30 分钟必晕，这是红线。

差异化 2

可玩的轻互动

13 个动效/彩蛋 ID，全部可关。炫技只在书架、发现、墨量页；阅读页只留翻页。

差异化 3

把死数据做成墨量

阅读轨迹、连续阅读墨迹、年度星图。单本轨迹用红色竖线标出切换版本时刻——全 App 最有说服力的一屏。

调研结论明确：共读是最贵且最不用做的伪需求。年轻人缺的不是书友，是"下一本读什么"。

01市场与竞品结论

横向拆解了云书阁、开元阅读、用心读书，另取微信读书（正版标杆）与开源阅读 Legado（聚合标杆）作参照。结论不铺功能表，只留能改变产品决策的部分。

三条被验证的真痛点

痛点证据产品回应
找不到对的下一本 "书荒"是伪需求，真需求是"选择困难"。用户书架有 200 本、读完 3 本。 发现页做「今天只推一本」，不推推荐流；读完自动给"下一本"而非"更多"。
读了记不住 笔记功能存在但无人用——因为记笔记的成本高于收益。 笔记标签化 + 书摘卡片化，一句话即可留痕；不追求完整笔记体系。
阅读数据是死的 所有竞品的统计页都只有"累计时长/册数"，看完即忘，无回访动机。 墨量体系：轨迹、墨迹、星图。把数据变成"我的阅读史"。

聚合类产品的原罪：书源腐烂

这是本次调研最重要的一条发现，直接决定了产品重心：

  • 规则失效——站点改版即批量失效，用户开机先测搜、搜完先校对。
  • 章节缺失——目录能拉到但正文空、或章节错位，用户要手动切换版本补。
  • 排版崩坏——各源 HTML 结构不同，同一本书切换版本就变形（字号、行距、段落全变）。
用户不是不愿意折腾，是不愿意一直折腾。产品要做的不是"支持更多书源"，而是"让一次折腾换来长期稳定"。

对应到设计上，就是本册反复强调的两条：切换版本前后排版零位移（剥离源样式，只取文本），以及状态必须诚实（见下）。

一条强反模式，必须写进设计红线

「假装有书的空书架」——加载中、失败、空数据全部伪装成有内容。年轻人对假数据的容忍度是零，一旦发现 App 在演，会立刻判定"这 App 是假的"并卸载。

因此所有空态/失败态/加载态都必须是真实且可解释的。原型里专门做了「书源管理」页作示范：3 个书源，1 个正常、2 个失效，并逐条写明失败原因（如"目录选择器未匹配到节点，疑似站点改版""请求超时 8.2s"），带重新检测按钮。禁止只说"导入失败"。

02合规结论与不可回退红线

本章不是免责声明，而是会直接改变产品结构的硬约束。共 7 条，分成两栏：左边是法律红线（碰了就是风险），右边是产品完整性红线（碰了产品就废）。

合规红线（5 条 + 1 补充条款，出现即判不合格）

#红线具体含义
1预置 / 内置书源出厂零书源，不内置、不推荐、不订阅下发
2书源市场、共享源榜单、聚合搜索不提供官方书源列表、不做跨站聚合结果页
3在线书源内容的缓存与下载仅本地导入文件可离线；缓存与索引目录排除 iCloud 备份
4与内容获取挂钩的变现会员解锁书源、广告、打赏、付费一律不做
5跨源自动补章只做手动切换后的位置对齐；"自动"二字是定性开关

补充条款（与前 5 条同级）：未成年人模式不得存在任何自动退出路径。系统年龄声明变化或联网重试即可解除家长主动开启的模式，等于绕开家长验证。须写成代码层类型约束——分龄请求凭据在 .minorConfirmed 下恒为 nil，语法上不可调用。
另：第 1、2 条在撰写红线时必须显式括注"含不提供书源二维码入口"。二维码是规则分发通道，无法用"我们不预置书源"吸收——红线写窄了，执行时就只守字面。

产品完整性红线（3 条）

#红线为什么不能退
1切换版本前后排版零位移渲染输入不含源样式（sourceStyleResidual == 0）。做不到，切换版本就是毁体验
2状态诚实（禁止"假装有书的空书架"）保留合规内核：这不是单纯体验问题。"假装有书"本质是"App 在提供内容"的外观，既是留存杀手，也是定性证据
3任何手势必须有非手势等价路径彩蛋可以藏，能力不能藏。只靠"摇一摇"才能换文件，即判不合格

此外两条不得退：正文区不得出现装饰性动效与玻璃（如实理由：实时模糊重算与温控/掉电指标不可兼得，不披合规外衣）；动效感知仅限 opacity 与 transform（改视口尺寸以扩大玻璃可采样区域，等于用未知量换面积预算）。

必须补齐的三处阻断级遗漏

  • 未成年人模式——开关、内容过滤、时长限制、家长验证。年龄分档采用四态：.adultConfirmed / .minorConfirmed / .ageUnresolved / .unverified。宵禁只给"确定未成年"与"未完成确认"两态（.ageUnresolved 套宵禁、不套时长、允许导入），.unverified 不套。详见第 8 章决策表。
  • 版权声明与投诉通道——应用内权利声明入口、侵权投诉表单、处理时限、重复侵权者处理、下架响应流程。
  • 书源规则凭据校验——导入时检测 Cookie/Token/Authorization 等字段，命中即拒绝。规则可能内含他人账号凭据，导入即构成非法获取数据。

独立风险：字体（不在上述 5 条内，但同等致命）

字体是唯一不会出现在任何设计评审里、只会出现在包体里的合规风险：

  • 按名称引用系统字体（如 PingFangSC-Regular）——无风险，可行。
  • 随包内置第三方字体文件——触发的不是小说版权，是字库著作权。中文商业字库维权活跃、判赔常见，无商用授权文件不得随包。

因此字体方案定为：苹方按名称引用（不随包）、思源宋随包（SIL OFL 允许嵌入分发，许可证本身就是授权文件）。截图里若出现特殊字体渲染，背后就对应着一份授权——这条也约束宣传物料。

随包 OFL 字体的三条实现要求（进打包清单）：

  1. 随包附许可证全文与版权声明（LICENSES/SourceHanSerif-OFL.txt）；
  2. 不得修改字形（若修改须改用新字体名，不能沿用原名称）；
  3. 不得单独分发字体文件（只能随 App 分发，不能做成可导出的字体资源）。

资质路径（发行前必读）

接入正版内容或做社区/评论/上传，会触发网络出版服务许可证；应用上架需 ICP 备案与 APP 备案；若做付费阅读另需相应经营资质。安卓渠道对"图书阅读类"要求许可证或内容合作证明——纯本地阅读器同样撞这道墙。

核心主流程

  1. 导入：用户粘贴/选择书源规则 JSON → 凭据字段校验 → 规则结构校验 → 落地。
  2. 搜索：输入书名/作者 → 并发查询已启用书源（限流 + 超时降级）→ 结果按可用性排序。
  3. 入架：选中结果 → 拉详情与目录 → 写入本地库 → 出现在「架上」。
  4. 阅读：打开 → 分章 → 首屏渲染 → 预加载前后各 N 页 → 进度落库。
  5. 切换版本（异常路径）：正文缺失/排版异常 → 手动切换版本 → 段落指纹比对 → 提示"已对齐到第 12 章第 3 段" → 渲染输入剥离源样式，排版零位移。
  6. 离线：仅本地导入文件可离线；远端内容不缓存。

墨量：把死数据做活

  • 年度阅读星图——极坐标散点，每个点是一本书，半径是阅读时长，角度是月份。
  • 连续阅读墨迹——横向累积条，连续天数越多墨色越浓。
  • 单本阅读轨迹——时间轴上标出每次阅读与切换版本时刻（红色竖线）。这一屏是全 App 最有说服力的证据：它把"我曾经为了读一本书折腾过几次"变成了可见的东西。

05设计系统：液态玻璃怎么用才不晕

液态玻璃的观感关键不是"磨砂"，而是折射——要有边缘高光、内部色调折射、微妙的色散。只用 backdrop-filter: blur() 做出来的是一层毛玻璃，廉价感立刻出来。

阅读引擎（技术难度最高）

  • 排版：优先 CoreText 自绘分页（TextKit 2 在超长文本与自定义避头尾上不够可控）。按容器高度切页，处理孤行寡行与标点避头尾。
  • 翻页：覆盖 / 滑动 / 仿真三模式。仿真翻页（curl）在 120Hz 下必须用 GPU 着色器而非逐帧重绘，否则帧率必崩。
  • 大文件：20MB txt 流式分章，增量布局，预加载窗口前后各 N 页。首屏渲染目标 ≤ 1s。
  • 编码：GBK / GB18030 / UTF-8 / UTF-16 自动探测，乱码兜底。
  • 段落指纹：段落首尾 200 字哈希 + 标题归一，切换版本后按指纹定位并容错匹配；对不上时降级为百分比并明示。

书源引擎与沙箱

  • 规则四类抽象：搜索 / 详情 / 目录 / 正文。表达式层统一 CSS Selector、XPath、JSONPath、正则。
  • 执行在 JavaScriptCore 隔离沙箱：无网络直连、超时与内存上限、崩溃隔离。主机侧只授予受限的 HTTP 能力。
  • 并发限流：多源并发上限可控，失败快速降级，请求去重，避免把用户手机变成爬虫。

五个必须优先验证的 POC

  1. 仿真翻页 120Hz 帧率——最可能推翻整个阅读器方案的项，第一优先级。
  2. 玻璃大面积模糊的 GPU 开销——A17/A18 上的实测拐点。
  3. JS 沙箱逃逸——书源规则的网络与文件访问边界。
  4. 20MB 文件首开——分章与增量布局的真实耗时。
  5. 书源批量失效的降级体验——10 个源同时挂掉时产品是否还站得住。

三个门面：把最容易被无声突破的约束变成可审计的

本轮真正的技术收获不是某个方案，而是把"规则"从文档搬进类型系统。能被编译器挡住的规则，不要写成文档警告。三条最容易被无声突破的约束，各自对应一个门面：

门面管什么做法
Fetcher 管「进」 唯一出网门面，未成年人模式下整体 denyAll；后台抓取任务不注册、导入模块不加载
Persist 管「存」 所有写盘路径必须经它，每条路径声明 payload 类型（用户文件/进度/笔记/第三方正文）。「第三方正文」这个类型在产品层不允许存在——不是禁用，是类型里没有。于是"不得落盘"从一条条款变成一个可 grep 的调用点清单
Degradation 管「出错」 任何 fallback 必须调 degrade(kind, declaresData:detail:)；声明必须落在降级申报清单（降级申报清单-墨见InkSight.md）里，CI 遍历 Degradation.Kind 全枚举做单测校验：清单未登记的 kind 令该单测失败、CI 挡合并（台账 D-15）

效力边界：三个门面各自买到了什么

这一节必须写清楚，因为总册是对外与审计的第一顺位文件，任何一处"已确保"被反问一次，整段可信度都会掉。

机制效力等级它真实买到了什么
Fetcher / Persist结构约束能力在类型层面不可表达。绕过它直接写 FileManager 本身即违规，且可静态检出
Degradation观测，非结构保证它不消除说谎的可能——有人可以直接写 declaresData: false。但它把"无意遗漏"降级成了"故意误报"，而后者是可追责的。它买到的是责任归属，不是正确性。
分龄权限令牌 AgeGateToken结构约束令牌只能由策略层产出且 .minorConfirmed 下恒为 nil，"自动重试分龄"在语法上调用不出来

原则：结构能守的用结构守，守不住的要有观测，两者都没有的地方不许写"已确保"。按此口径，本册对 Degradation 一律表述为「已识别并缓解」，不写「已确保」。

矩阵三值：让"假文案"在结构上生成不出来

设计侧发现发行版里写「在线功能不可用」是一句假话——发行版根本没有在线功能，不是"有但被禁用"。声明一个不存在的限制，和声明不存在的内容一样是虚假陈述，只是方向相反。

根因是能力矩阵用二值（✓/✗），无法区分"受限"与"不存在"。修正为三值，并增加构建变体维度：

单元格含义派生文案
✓可用无需说明
✗存在但受限「…不可用」合法
∅不存在必须沉默——结构上不生成任何表述

矩阵增加 buildVariant ∈ {research, release}；文案键从 state 改为 (state, variant)，且只能从矩阵派生，禁止各屏手写。效果：发行版里那句假话从结构上就生成不出来，而不是靠两套文案各自维护（后者迟早漏一处）。

连带影响：NFR 验收须注明适用变体（如"在线端到端 P50 ≤2s"仅适用研究版）。

工时与定性的作用

增量工时 5.5 人日（自绘阅读器层 3.5 + 自绘浮层 1.5 + 降级声明结构 0.5）；排版引擎 2.0 人日计入基线，不占增量。累计勘误 3 单，均走定点替换，不升版本号。

关于"给约束定性"，值得记一句：定性不只是分类，它决定推翻难度，也决定谁有资格推翻。定性成"优化"，任何有写权限的人觉得没必要就能推翻；定性成"合规要求"，要推翻必须拿出合规结论——而多数想推翻它的人拿不出。难度可以被勤奋克服，资格不能。

一条可复用的方法：给规则找一个"明确不该适用"的对象

找不到反例，说明这条规则还没有边界，此刻它一定会被外推。

它的好处是不依赖自觉——不要求人停下来想清楚，而是要求交出一个具体物件；交不出来是可见的。

这解释了本轮的一个现象：那几条被用宽的规则（"联网/导入"一刀切、宵禁定性、开启模式措辞），全都没有反例；而经得起推敲的判据（提示方向、可逆/不可逆、我方能力 vs 用户设备状态），每一条都自带一个反例。判据能防外推，不是因为写得更细，是因为它自带反例。

08开放问题与下一步

已裁决，不再讨论

  • UIT1 三指下滑永久不做，改 chromeToggle（点击正文中央，唯一入口）。三指是 iOS 系统保留手势（轻扫撤销、双击缩放、辅助功能三指拖移），系统优先级高于 App；开启辅助功能后该入口会"看起来存在但按不动"，属无障碍缺陷。阅读器内仅保留 EGG4 一个手势。
  • 枚举统一：versionSwap / switchRipple / edgeBack / chromeToggle。枚举名不得描述已被否决的旧行为。
  • 字号定 19 / 20 / 21 三档；原「低于 18pt 自动切高对比」整条作废（三档全属大字，5.4:1 恒合规，不需要补丁）。
  • 夜间对比度拆两档：柔和 5.4:1（默认）/ 高对比 12.1:1（可选）。
  • 阅读器锁竖屏（其他界面不受限）。横竖切换需全量重分页，代价大于收益。
  • 字体白名单 2 款：PingFangSC-Regular 按名称引用、不随包（Apple 字体许可不允许随包分发）；思源宋随包（OFL 许可）。降级链自动回退系统默认字体。
  • 年龄四态，UI 三态：.adultConfirmed / .minorConfirmed / .ageUnresolved（旧称 provisionalMinor）/ .unverified。
    界面三种说法：①「未成年人模式」　②「年龄信息未完善 · 未成年人保护已生效」（.ageUnresolved，因为它会宵禁，界面说的话必须和行为一致）　③「年龄信息未完善」（.unverified，按构建分版：研究版才追加「在线功能不可用」，发行版不写（台账 D-02；旧词「实验功能不可用」全案作废）。
    统一文案（与视觉规范、PRD 三处一字一致）：「年龄信息未完善 · 未成年人保护已生效，完善后即可继续阅读」。
    三处取舍：①用"未完善"不用"未确认"（前者指向用户可做的动作）；②不写"网络可用时将自动确认"——那是被动承诺不是动作路径，用户会干等；③必须保留"未成年人保护已生效"——它既是该态套宵禁的正当性来源，缺了这句，宵禁在用户眼里就成了一个没有解释的 bug。
    命名原则：内部名描述事实，UI 名描述行为。内部叫"年龄未解析"（事实），界面说"保护已生效"（行为），各自准确。
  • 动作词单一叫法：只叫「导入」，不造别名。「导入」的禁令只在 .minorConfirmed 内成立（那里本就没有这个入口），其余状态是真实功能，应当照实叫。一致性不该靠改名实现，而该靠"同一个功能只有一种叫法"实现。
    .ageUnresolved 与 .unverified 必须保留导入入口——否则离线首启的成年用户会面对空书架且无法加书，App 完全不可用。闭环靠事后补审，不靠事前禁。
  • 状态矩阵是唯一真源，同时承载行为与文案。矩阵里直接写状态条主文案、caption、空态动作词；视图层禁止 if state == .xxx 各自拼文案。好处有三：禁词检查只需对矩阵做一次而不是每屏一次；矩阵改文案强制跟着改；三态状态条从矩阵派生。两套真源必漏一边——本轮按钮被撤掉后文案没跟上，就是活例子。
  • 两态都不给「完善」按钮，只给一行文字路径：设置 › Apple 账户 › 个人信息 › App 年龄段。理由两条——iOS 无法 deep-link 到该系统页（按钮点了无处可去），而若把按钮做成"触发一次分龄请求"，就等于我们已否决的"点一下就变普通模式"的解锁路标。点不到东西的按钮，比没有按钮更伤。
  • 宵禁拦截页定稿文案：「年龄信息未完善 · 完善后即可继续使用」＋ 上述路径。不出现"联网"（属未成年人模式专项禁词）、不出现"退出／解锁／切换／跳过"、不放任何可点按钮——它是解释，不是出路。
  • 宵禁与导入的定稿口径（行业专家终审）：
    状态宵禁时长限制本地导入
    .adultConfirmed不套不套允许
    .minorConfirmed套套禁
    .ageUnresolved套不套允许
    .unverified不套不套允许
    宵禁只区分"确定未成年"与"未完成确认"两种处理，但两者不同：.minorConfirmed 禁新增导入（家长筛完怕被下次绕过）、套宵禁与时长；.ageUnresolved 允许导入（无家长动作即无筛选可绕过）、套宵禁但不套时长。
    同一个判据推出两个方向：宵禁误伤可逆（当晚不能读、次日恢复、联网即解）故保留；禁导入与时长误伤不可逆（书没了、额度被吃掉）故豁免。
    且该状态不设"超期自动降级"：因为 .ageUnresolved 套宵禁而 .unverified 不套，降级即放宽——断网一周就能免宵禁，这是一条可等待的绕过路径。改为持续到获得确定答案：重试 3 次后收回"网络可达性"触发器，仅由冷启动 / 回前台 / 从系统设置返回触发；成功后当场解除并恢复阅读，不要求用户重新进入。
  • 宵禁拦截页是解释，不是出路：文案不得出现「退出／解锁／切换／跳过」，且不得有可点按钮。这条极容易被"提升体验"改成"去设置"按钮——那就是被删过两次的东西。
  • 元数据与提审自查由产品经理兼管，行业专家复核；优先做截图与商店描述（一旦提交即固化、且历史版本可被抓取存档），后做界内文案。
  • 阅读轨迹的切换版本时刻标记改中性小圆点，不用标红——标红是自曝，会被截图当缺陷证据。

术语规范（用户可见文案）

原词处置理由
换源必须改 → 切换版本 / 切换文件"换源"读起来是"我们在操作多个来源"，属自认。这条没有豁免
导入主链路保留原词；未成年人模式界面内不出现"导入自己的书"是核心定位。为避讳改掉主功能名，属过度合规
搜索主链路保留原词；未成年人模式界面内不出现该功能在未成年模式下不存在，无需替代词

代码标识符（SourceEngine 等）内部保留，但不得出现在用户可见字符串、日志、遥测、崩溃报告、导出文件里。

一条收窄的判据（避免禁词表被用过头）：同一个词，描述我方能力时禁，描述用户设备状态时不禁。
「联网」不能说"我们联网后会自动确认"，但可以说"设备离线"；「导入」不能说"导入我们的书库"，但可以说"导入你的文件"。禁词表要防的是留下"我们提供内容"的表述，不是让产品失去表达能力。

标识符的第三条边界（最容易漏）：不得出现描述"我们不做的事"的标识符。SourceMarket／RuleHub／SubscriptionFeed 这类命名，即使从未被调用、只留了个空壳，也是"我们曾经计划做"的证据。描述现有能力的命名可以留，描述已移除能力的命名必须不存在——这是"能力本身不能存在"在命名空间里的版本。
