# 行业合规与风险意见书 · 墨见 InkSight（v1.1 定稿）

行业专家 顾纵深｜对应 PRD v1.6 / 架构 v1.2｜v1.1 增补：残余风险口径、未成年人模式最终结论、埋点取证红线、不可回退项

## 结论先行

「聚合书源 + 用户导入」在中国现行法律框架下**不是灰色地带**，而是已有刑事判决确认的高风险侵权模式。以原始形态发行，**风险等级为阻断级**。

经 Phase 1–4 收敛后，项目状态判断为：**在"研究用途 + 功能收敛"前提下，法律风险已从阻断级降至可控级**，前提是所有已确认的收敛动作一个都不回退。

## 一、版权与侵权风险定性

**1. 提供行为**
把第三方站点内容深度链接、格式转换后嵌入自有阅读界面，使公众在个人选定的时间与地点获得作品，落入著作权法关于信息网络传播权的控制范围。司法实践已确立「**用户感知标准**」——内容是否存于自己服务器不再是免责理由；只要用户主观上认为作品由本 App 提供（无跳转、无来源标识、统一排版的"纯净阅读"），即认定为本 App 的提供行为。这直接击穿「服务器标准」。

**2. 帮助与教唆侵权**
依最高法关于审理侵害信息网络传播权民事纠纷案件的司法解释口径：以推介、技术支持等方式诱导、鼓励用户侵权构成教唆；明知或应知而未删除、屏蔽、断开链接构成帮助侵权。**编写并分发针对特定盗版站的抓取规则，正是典型的技术支持型帮助。**

**3. 刑事风险**
上海闵行区检察院办理的"×读"案，已以侵犯著作权罪对开发者与推广者提起公诉并获有罪判决。定罪核心不是"存不存内容"，而是：①主动编写针对特定盗版站的抓取指令；②系统性聚合、分类、排行；③社群运营推荐引流；④以营利为目的。绕过付费墙与 DRM 另涉规避技术措施。

**4. 「技术中立」成立与不成立的分界**

| 抗辩成立 | 抗辩崩塌 |
|---|---|
| 只提供通用解析能力，规则由用户本地自备 | 内置/预置/推荐/分发书源 |
| 不做选择、编辑、分类、排行、推荐 | 有书源列表、书源市场、书源订阅 |
| 保留跳转与来源标识 | 深度链接后渲染"纯净阅读"、屏蔽原站广告 |
| 不对该流量变现 | 会员 / 广告 / 打赏 / 买量 |
| 收到通知即断开、有重复侵权处置 | 拖延，或仅删除个别链接 |
| 已采取合理有效技术措施仍难发现 | 明显侵权事实（知名付费作品免费可读）而放任 |

**中立性是"能力中立"，不是"意图中立"。** 一旦把规则、聚合、推荐、变现任一环握在手里，抗辩即崩。

## 二、关键结构判定

**① 跨源自动补章 —— 已移除，且不得回退。**
App 自主决定章节来源并完成拼接，产出原站不存在的"合成完整版"，这是"实质性替代"的最强形态；"自动"二字使工具属性消失，同时落入帮助侵权与"用户感知"双重认定。**它比聚合搜索更危险，因为它让用户从"找到"变成"拿到完整"。**

**② 在线书离线缓存 —— 已移除。**
持久化落盘与聚合搜索不是同一量级：聚合只涉及展示与链接，落盘是对作品表达的固定与再现，同时命中 App Store 5.2.3 与复制权。

**③ 书源二维码入口 —— 已移除。**
二维码是规则分发通道。App 一旦能生成或识别它，角色就从"用户自备规则的解析器"变成"规则分发节点"。

**④ ⑤ 页从「换源面板」改为「换一个版本」—— 结构修正。**「位置对齐」这一能力本身完全合法，它只把两份文本的同一段对上；有风险的从来是"对齐的对象是第三方抓取内容"。改为本地多副本后，能力全额保留、风险归零。更深一层的判断：**P0 转场不能挂在一个 B 版上线后必被删除的功能上，这是结构问题，不是文案问题。**

**⑤ 字体（独立 IP 风险，与小说版权无关）。** 按名称引用系统字体无风险；**随包内置第三方字体文件触发的是字库著作权**，中文商业字库维权活跃、判赔常见。口径：**随包仅允许 SIL OFL 等明确允许嵌入的字体，且必须随附许可全文与版权声明**——OFL 本身即授权文件，无需另取商用授权，但只带字体不带许可等于自行丢弃合规依据。另两条边界：不得把字体作为可单独提取的资源暴露；不得在市场材料中把字体作为我方资产宣传。隐蔽点在于：该风险不会出现在任何设计评审里，只会出现在包体里；而商店截图若呈现特殊字体渲染效果，背后即对应一份授权。


## 三、资质与备案

**确定要求**：ICP 备案（域名解析至境内服务器）、APP 备案、软件著作权登记、公安联网备案、个人信息保护合规。
**实务中通常要求**：等保二级备案测评（有账号体系时）。
**功能触发型门槛**：接入正版书城或付费阅读 → 网络出版服务许可证 + 经营性 ICP 许可证（均必须）；用户上传内容公开可见或设社区评论 → 网络出版服务许可 + 网络文化经营许可证；有声书 → 信息网络传播视听节目许可证（极难获批，只能合作持证方）。
**上架阻断点**：国内安卓商店"图书阅读类"硬性要求提供网络出版服务许可证或内容合作证明——纯本地阅读器亦会撞上，需提前设计持证方挂靠结构。

## 四、未成年人保护（最终结论）

核心判断：**未成年人模式的价值不在"默认开"，在"开到底"。默认开但功能照旧的模式会被认定为规避义务，比不设更糟——这与 2.5.19 是同一类问题。**

- 不做"首启即未成年人模式"。该模式的触发基础是"用户是未成年人"或"监护人开启"，不是推定所有成年人为未成年人；逼成人自证成年要收集年龄或身份信息，反与个保法最小必要冲突。
- 首启做四态分龄（v1.1 修订，替代原"三支"方案）：
  - `.adultConfirmed` → 普通模式；
  - `.minorConfirmed`（系统声明未满 18 **或家长主动开启**）→ 未成年人模式，**任何情况下不得自动退出**，不设自动重分龄通道；
  - `.ageUnresolved`（原 `.provisionalMinor`，年龄不可得后保守进入）→ 未成年人模式，**套宵禁 + 不套时长限制 + 允许导入**；获确定答案即解除，**不设自动降级**。
  - `.unverified`（用户主动选择不共享年龄）→ **未验证态**，本地能力全可用，不套用宵禁与时长限制，不提供任何联网能力，以非阻断提示引导"完善年龄信息"，且提示须含「如本设备由未成年人使用，请开启未成年人模式」。
- **"禁止新增导入"仅适用于 `.minorConfirmed`**。推断态与未验证态必须允许本地导入——否则离线首启的成年用户面对空书架且无法添加任何书，App 完全不可用，而"导入你自己的书"是 B 版全部核心功能。正当性：家长筛选只在家长主动开启的场景下才有对象，另两态无家长动作，无可绕过之筛选；推断态日后收敛为确定未成年时，由家长内容确认流程补审。
- **宵禁与时长限制的适用范围（v1.2 修订，取代前版结论）**：按《指南》，时间管理属未成年人模式的**模式内默认设置**，不以家长动作为前提，家长只有豁免权、无授权义务。
  - `.minorConfirmed`：套宵禁 + 套时长限制 + 禁导入。
  - `.provisionalMinor`：**套宵禁 + 不套时长限制 + 允许导入**。→ 已更名为 `.ageUnresolved`。
  - `.unverified`：不套宵禁与时长限制，允许导入。
  - 切分依据：**代价可逆的保护保留，代价不可逆的保护豁免。** 宵禁误伤 = 当晚不能读，次日恢复、联网即解，可逆；时长限制误伤 = 当日额度被吃掉，累计型、不可恢复，不可逆。
  - 理由之二：**标签自带义务。** 一旦在 UI 上呈现为"未成年人模式"，该模式就必须按模式行事；模式内缺时段管理，"未成年人模式"即降格为标签。且**保护应当随不确定性上升，而非下降**。
  - `.unverified` 不属于标签自带义务的情形（不是未成年人模式、UI 亦不如此命名），但常驻提示须含「如本设备由未成年人使用，请开启未成年人模式」——不强制推定，但使"一键受保护"显性可见。
  - 宵禁拦截页文案不得出现"退出／解锁／切换／跳过"，不得提供任何可点击按钮：它是解释，不是出路。
- **`.ageUnresolved` 不设自动降级**（v1.3 修订，取代原"7 天降级"结论）。原规则意在防"临时状态变无限期免限"，但该态既已套宵禁即不免任何限，前提消失。更关键：**"等 N 天即免宵禁"是一条可等待的绕过路径**，与否定"等联网返回成年答案"的理由完全相同，且更简单（断网一周即可）。替代方案：保持该态直到获得确定答案；重试降频而非停止（收回"可达性变化"这一高频触发器）；界面持续显示「正在确认年龄…」；拦截页给出精确路径（设置 › Apple 账户 › 个人信息 › App 年龄段）；重试成功即当场恢复阅读。
- **成人误伤的救济是"30 秒可解"，不是"等 N 天自动放行"。** 给成年人一条"等待即解"的路，等于给未成年人一条同等的路。
- **可达性事件可作为分龄重试的触发器，不得作为任何抓取或预取任务的触发器**，否则等于以系统信号绕过 denyAll。
- **不得存在任何自动退出未成年人模式的路径**：系统年龄声明变化或联网重试即解除家长主动开启的模式，等于用技术手段绕开家长验证，违反防绕过硬要求。这是最容易被"优化体验"改掉的一条。
- **fail-closed 的边界**：守的是"不得因拿不到数据就放开内容接入"，其对象是内容。B 版不存在业务出网，"可放开的内容接入"没有对象。该守的是不放开内容，不是扣住成年人。强制套用会把成年用户永久锁死，产品事故确定、合规收益为零。
- 状态来源须留痕（本地日志只记分支类型：系统声明／家长开启／推断／未验证；不记年龄段数值、不上报），监护争议时是唯一自证材料。
- **"从未启用"与"绕过已启用"必须分清。** 保护的对象是**已生效的限制**，不是"可能生效的限制"。`.declinedSharing` 不是未成年人能自主产生的——年龄共享由 Apple 账户／家庭组织者控制，不在孩子手里；家长从未做过任何设置时，保护从未被启用，该状态不是"绕过"，而是"从未开始"。一旦家长启用过，状态即进入 `.minorConfirmed`，此后任何路径不得自动退出——真正需要防的绕过只存在于保护已生效之后，而该路径已封死。
- UI 语言判据：**模式内「永不可用」的能力 → 不出现；「可被家长配置」的能力 → 家长设置内作为控件呈现。** 禁用态暗示"有朝一日会开"，是给可豁免功能用的语言；书源在模式内不存在任何豁免路径，故不得以禁用态呈现。
- 「关于本模式」用正面列举（我能用什么），不用负面解释（你被禁止什么）。正面列举比负面解释更不构成剥夺叙事。
- 进度：模式内独立存储，退出时**自动归位**，不弹选择框。理由不是抗辩，是投诉——合规风险能用设计兜住，体验缺陷兜不住。
- 分级：用户导入文件无分级元数据，由家长手动标记适龄或隐藏；进入模式时设家长内容确认，并与隐藏清单**成对存在**（单有前者会被"下次导入"绕过）；模式内禁止新增导入。
- 日志边界：模式内**不产生网络日志与行为上报**，本地保留必要的安全与故障日志。安全日志是护身符，行为上报才是负担。

**残余风险（对外材料必须如实表述，不得写"已消除"）**

> 未成年人模式下，业务代码的出网调用集中在单一 `Fetcher` 门面并整体 denyAll；后台抓取任务不注册；导入模块不加载。iOS 平台不提供进程级断网能力，此为**残余风险**，非已消除项。
> 使用时长采用单调时钟统计，不受系统时间修改影响；22:00–6:00 时段判定依赖系统时钟，存在理论绕过可能，已通过系统时间跳变检测与异常记录**缓解**，此为**残余风险**。

**叙事纪律**：「未成年人模式断网」与「在线书续读需联网」不得在同一份材料中并列而不给解释，否则会被追问"既然断网是安全设计，为何成年人不也断网"。标准答法是定性为**产品裁剪**而非**安全补救**：不是因为判断联网内容存在合规风险，而是未成年模式的定位本身就是本机图书阅读器——儿童手表不提供浏览器，不是因为互联网违法，而是儿童产品做功能裁剪。此定性亦与分龄监管导向一致。

## 五、隐私、数据与取证

- 个人信息保护法：最小必要、敏感信息单独同意、本地优先、不跨境。
- **书源规则携带 Cookie/Token 属隐性高危**：等同代持第三方账号凭据，泄露或用于自动化登录可能触及非法获取计算机信息系统数据。硬约束：凭据不落盘、不云同步、不上报、不明文；导入时静态扫描命中即整条拒收。
- **索引与缓存边界**：判据是"是否形成稳定可再现的副本"，不是文件名或目录名。全文索引仅对用户本地导入文件建立；在线书只允许存章节序号、标题、字符偏移与**首尾指纹哈希**（哈希不可逆、不构成复制），表结构层面不得存在正文字段。所有缓存与索引目录设 `NSURLIsExcludedFromBackupKey`，否则等于把第三方内容同步上云，从"本地存储"升级为"向公众提供"。
- **埋点与日志的取证红线（原清单未覆盖，v1.1 新增）**：埋点与服务端日志的字段名与取值是最容易被整套拿走的证据。**不得记录任何第三方域名、站点名称、书源标识**（哈希与缩写亦不行，可枚举比对）；可记事件类型与计数，不可记指向具体第三方的标识。**"只落本地、不上传"不构成取证保护**——电子数据鉴定的标准动作就是镜像设备、解析本地库，本地数据不是安全区，恰恰是最先被拿走的部分。
- **权利管理信息保护**：净化规则不得去除版权声明、"本书由…提供"、"仅供试读"、"请购买正版"、译校者署名等行。去除权利管理信息本身构成独立的违法行为，且在诉讼中直接证明主观故意。

## 六、App Store 审核

- **5.2.2 / 5.2.3**：使用第三方服务须获其条款许可；不得协助非法文件共享，不得提供保存/转换/下载第三方媒体能力。抓取类能力几乎必然触发。
- **1.2**：UGC 需具备内容过滤、举报机制、封禁能力、公开联系方式。
- **2.5.19**：禁止审核时隐瞒真实功能、"先过审后解锁"。把能力藏进"开发者选项"骗审，后果为下架＋终止开发者账号。
- **元数据是 5.2 拒审最高频触发表**：名称、副标题、关键词、描述、截图不得出现"书源""聚合""全网免费"；截图不得出现真实站点名与域名。界面做干净但元数据带词，一样被拒。**更新说明是删不掉的历史快照。**
- **免责声明的反向自证陷阱**："本 App 不存储任何内容，内容均来自第三方""所有内容均由用户提供""仅供学习交流请 24 小时内删除"——三条均属自认。正确表述：正向陈述"仅解析用户本地文件，不提供内容来源"。

## 七、不可回退项（出现即判验收不合格）

结构由 team-lead 最终确认（A 栏 + 补充条款 + B 栏），以下为定稿。

### A 栏 · 合规红线（5 条）

1. **不预置、不推荐、不订阅下发任何书源**
   ——**显式括注（不改变条文，仅为可查性）**：书源二维码的生成与识别属"订阅下发"通道，同在本条禁止之列。二维码是最隐蔽的分发形态，若不点名，评审时容易只想到"列表"和"链接"。
2. **不做书源市场与跨源聚合搜索**
3. **不缓存、不下载第三方内容**
4. **不变现**（会员／广告／打赏／付费一律）
5. **不做跨源自动补章**

**A 栏补充条款（与前 5 条同级）：未成年人模式不得存在任何自动退出路径。**
依据：系统年龄声明变化或联网重试即可解除家长主动开启的模式，等于用技术手段绕开家长验证；这是防绕过硬要求里最容易被"优化体验"改掉的一条。

### B 栏 · 产品完整性（3 条）

1. **切换版本前后排版零位移**

### 分栏的理由（须与清单同时留存）

把产品完整性项放进合规栏，会让合规栏看起来像洁癖清单，从而稀释真正的红线——**六条混称会让四条变轻**。故两栏分列、措辞统一为"出现即判不合格"，A 栏置于原型验收记录第一屏，不入附录。

**以上任一单独回归，均足以把定性从可控拉回阻断级。**

## 八、一句话立场

合规不是只能删功能。**很多时候功能是干净的，有问题的是它承载的对象。** 本项目最有价值的合规产出不是砍掉了什么，而是把「位置对齐」从有风险的对象上摘下来、装到了合法的对象上。同理，**不要让合规变成砍掉一切趣味**——本项目主张移除的始终只有四类：抓取、跨源拼接、正文落盘、规则分发；转场、玻璃、皮肤、手势彩蛋全部无风险。

另附一条通用原则：**命名与宿主必须同迁。** 一个被改名的动效或功能，若仍挂在原链路上，本质未变反而多出"刻意规避表述"的痕迹，比原名更糟。改名只能解决词面，解决不了它落在哪。
