## A. 原生可实现面：我的材质规范要降级为「原型表达」

架构指出的事实我全部接受，并据此重写材质章节的定位——**之前我把 CSS 配方写成了"实现配方"，这是错的**。

| 我原来写的 | 事实 | 处理 |
|---|---|---|
| 四层折射（conic 高光环 / 径向体色 / 色散双环 / feTurbulence 噪点）、`mask-composite`、`plus-lighter` | 全是 Web/CSS 概念，iOS 原生无对应 API；SwiftUI 叠四层半透明 View ≠ 玻璃 | **§2.2 四层降级为「原型与设计稿表达层」**，只用于 HTML 原型与视觉稿，不得作为开发交付配方 |
| `--refract` / blur / saturate / brightness 作为可调参数 | 原生 `glassEffect` 内部结构不开放，**这些参数没有对外入口** | 改为「设计意图记录」，用于描述目标观感；原生只能控 **tint / interactive / `strokeBorder` 1pt / 形状** |
| Thin 档 = `.glassEffect(.clear…)` | `.clear` 定位是"叠在照片/视频/地图上"，背后需强对比媒体 + 上层压暗；用在 TabBar/胶囊/Toast/吸底条上 → 正文可读性跌破 WCAG、且**浅底上玻璃边缘整体消失** | **Thin 档改 `.regular` + 低不透明度 tint（0.10–0.18，我取 0.14）**；`.clear` 仅保留给"阅读页浮层压在大幅封面/插图之上" |
| TabBar 项 = Thin 档 | iOS 26 系统 TabView 的 TabBar 材质由系统渲染，**没有任何 API 用 glassEffect 自定义系统 TabBar**，只能 `.tabBarMinimizeBehavior(.onScrollDown)` 控折叠 | **规范里删除「TabBar = Thin」**，改标注「系统接管，不承诺像素级还原」；原型里画的效果仅示意 |
| `GlassEffectContainer(spacing: 20 / 32)` | spacing 是**融合阈值**不是视觉间距，且**单元素容器无作用** | 改为「待 POC-2 真机校准」，现在不填数；继续阅读卡是单元素，不需要该参数 |

**验收口径随之改变**：原型按 CSS 验收（可像素比对）；原生按**观感等价**验收，**不得要求与原型像素级一致**。这条要写进原型验收清单，否则会拿一个物理上做不到的标准去卡开发。

**性能路线**：采用路线 A（系统 `glassEffect`）——零实现成本、性能系统保证、`Reduce Transparency` 自动处理；路线 B（Metal 自绘）明确不采用（2–4ms GPU/帧，与翻页 118fps 抢同一 GPU，A17/A18 实测大概率 40–50fps）。
**降级顺序按架构重排**（若未来仍走自绘）：① 砍噪点层（帧率代价最大、观感收益最小，且噪点必须预渲染静态平铺，逐帧重算必崩）→ ② 砍色散双环 → ③ 折射降为「静态高光 + 体色」两层（**保留 blur**）→ ④ **最后才降 blur**（blur 是玻璃的存在感来源）。底线不变：**降级后仍是纯色 + 1pt 描边，不得变成半透明糊块**。

### A.1 T1 实现定案与必须写进规范的两个坑

采用**全屏 overlay + 快照 + 坐标换算**（排除 `matchedGeometryEffect`：跨容器拿不到动画；排除 `UIViewControllerAnimatedTransitioning`：绑死 NavigationStack 语义、系统管快照反而难做"可关到零动画"）。

1. **书脊轴在 iOS 的写法**：`CATransform3D` 没有 transform-origin。实现为 `layer.anchorPoint = CGPoint(x: 0, y: 0.5)` 并**同步补偿 `layer.position`**（不补偿图层会跳位——这是最容易出错的一步）；`perspective 1200` 用 `m34 = -1/1200`。
2. **z 序澄清**：我表里的「封面 z3→z0」是**快照层内部的 z 变化**，快照层整体在 z3；正文 z4、返回按钮玻璃 z5 不变。
3. **T1 380ms 期间书架侧玻璃必须冻结或转不透明**——卡片翻转时 backdrop 逐帧重算，会和 T1 抢帧。
4. **380ms 加余量标记**：首帧需一次位图物化，可能超预算；POC-1 出「首帧耗时」后再定是否补 40ms 起步缓动。规范里标为 `T1-duration: 380ms (pending POC-1, +40ms reserved)`。

### A.2 「全局总关」的语义纠正（我的验收口径要改）

我原来写「任何动画时长 = 0」是**错误实现**——`.duration(0)` 下 `matchedGeometryEffect` 仍会用旧 frame 画一帧。正确语义是「**不播动画路径**」：`withTransaction(Transaction(animation: nil))` + `AnyTransition.identity` + 彩蛋不创建视图。
**验收改为**：首帧与末帧**逐帧 diff 为 0、无中间帧**（而非检查 `duration == 0`）。v1.1 的 4.3 关闭态表按此改写检查点：
- T1：逐帧 diff=0、无中间帧、无残影层（原文"首行 y diff=0"保留为其中一项）
- T2：卡片尺寸 diff=0、竖排断行不变、源色为终值
- T4：落位 rect 与关闭前一致、无 1.02 过冲中间帧

## B. 换一份文件（⑤ 页语义替换，industry 定）

⑤ 从「换源面板」改为「**换一份文件**」：同一本书的多份本地副本（txt / epub / 不同译版 / 不同修订稿）并存，切换后位置对齐。**这永久合法（全本地、用户自有），T2 因此有了不受 B 版退化影响的 P0 宿主**——这是我之前那个断点的正解，比"改文案保在线换源"干净得多。
在线书源按 (c) 下沉「我 → 高级」，且**保留真实名称「书源（实验）」**，不改叫"实验功能"（藏词本身是隐瞒功能）。

## C. 浮层与正文的关系：上移，但绝不遮罩（PM 纠正，我改）

我 v1.2 写的「浮层出现时正文整体上移/变暗」——**"变暗"作废**。正文区不叠 scrim 是硬规则：scrim 会压低正文对比度，与夜航 7.2:1 的门槛自相矛盾。
定稿：**浮层出现时正文整体上移 320pt 让位，浮层占据原正文区域；正文全程零玻璃覆盖、零遮罩、零变暗。**
上移后顶部露出的区域用**主题底色 + 1pt 细线**填充，不用模糊、不用玻璃（否则又多一处玻璃）。

## D. 12 页裁定（PM）

**11 页可点击 + 1 页静态**：⓪ 首启分龄进可点击流程（合规入口，点不到等于没演示）；⑪ 未成年人模式**静态图 + 从「我」页进入的跳转**（长驻状态页，不需走通内部每个操作，但入口必须点得到）。

## E. 合规红线清单落地（industry 给，我逐条转成可自查项）

**颜色**：禁红色表达限时/即将结束；未成年模式禁高饱和强调色做"更多/解锁"引导；书源实验标识用中性灰或琥珀（禁绿、禁品牌主色）；玻璃不得使正文对比度低于 7:1（普通模式亦适用）；主色与字体不得接近头部阅读平台品牌识别组合。
**动效**：**任何动效不得延迟"限制生效"的呈现**（时长到点立即中断，禁"优雅淡出 30 秒"，那 30 秒就是绕过）；22:00 未服务卡用直切（禁弹入/上滑，庆祝感会把"被限制"读成"被奖励"）；书源实验标识禁庆祝动效（撒花/脉冲/光晕）；趣味转场仅普通模式非书源链路。
**文案**：禁用词——书源、换源、搜书、找书、书库、全网、免费看、海量、聚合、破解、去广告、纯净版、无限；禁"免费"作卖点；**免责声明禁写"本 App 不存储任何内容，内容均来自第三方"**（这句是自认提供第三方内容），正确为「仅解析用户本地文件，不提供内容来源」；分级用"家长标记"不用"已评级"；空态不说"换个源试试"。
**元数据专章（转 team-lead 与产品）**：App Store 名称/副标题/关键词/描述/全部截图禁出现"书源""聚合""全网小说免费"；截图内禁真实第三方站点名、域名、水印。
**时长条**：不做消耗型视觉（禁血量条/倒计时紧迫感），不足时中性提示，不红色闪烁。
**22:00 卡**：禁任何可点"家长豁免"入口。

## F. 分龄失败分支与监护验证（industry 三条 + 三条）

分龄 fail-closed：① **失败分支不得提供"以成人身份继续"逃生按钮**；② 文案改为「未能获取年龄段，已按未满 18 岁处理 · 去系统设置调整年龄共享」（给真实出路）；③ 直接进模式，**不用"我们没能确定"的不确定表述**，用确定语气。
监护验证：① **生物识别只能是家长的**——默认 6 位码，生物识别仅在设备已录家长特征且由家长显式开启时作为便捷通道；② 错误次数渐进延迟，**不用"再错就锁死"胁迫文案**；③ "忘记密码"只能走重置（清空模式内进度 + 重设），不能是跳过。
「未成年人模式」入口升级为**独立分组内 c16 描边卡片 + 一行说明**；chip 真实反映状态；"未开启"不用红色。
