## A. ⑤ 页文案去禁词（PM 指出，我犯了）

我在 pin 行写了「当前：xxx.txt · 2.1MB · **精校版**」——"精校版/全本版/全集/完结版/补全/完整版"属 UI 与元数据禁词：**暗示"我们提供完整内容"会触发网络出版资质联想；更关键是"全本"是我们无法履行的承诺，用户拿去对质缺章时就是产品事故。**

**改法**：
| 位置 | 原（错） | 现 |
|---|---|---|
| pin 行 | 当前：xxx.txt · 2.1MB · **精校版** | 当前：xxx.txt · 2.1MB · **未命名版本**（默认值） |
| 版本标签 | 我方提供的"精校版/全本版" | **用户可编辑纯文本**，默认留空显示"未命名版本"，**我方不预置任何值** |
| 主按钮 | 替换当前文件 | 「**换一个版本**」 |
| 次按钮 | — | 「**版本对比**」 |
| 对齐提示 | — | 「**位置对齐**：已对齐至第 12 章同一段」（"位置对齐"本身可用） |
| 允许词表 | — | 替换为其他版本文件 / 换一个版本 / 版本对比 / 位置对齐 |

## B. UIT1 定稿：单一行为 + 两入口 + 取消自动恢复

**收益**：PM 取消「6 秒自动恢复」一举解决两个问题——① 用户专注阅读时 chrome 自己弹出，是最粗暴的打断；② 省掉一个 6 秒定时器（架构侧刚提醒过"3 秒定时器都要挂降帧机制"）。
**并且这条顺手解掉了架构的反对**：他反对"合并"是因为关闭态语义会分裂（专注还锁不锁 chrome？）；现在 UIT1 只有**一种行为**（显隐），专注 = chrome 收起态，不是独立概念 → 不存在分裂。

| 项 | 结论 |
|---|---|
| 行为 | chrome 显隐（唯一行为） |
| 入口① | **点击正文中央**（必做，可发现性最高） |
| 入口② | 三指下滑（**待架构复核**：他已技术否决——与系统辅助功能三指手势抢占，失灵场景恰是最需要可达性的用户。我按"可选、默认不画"处理） |
| 自动恢复 | **不做**。恢复靠再点中央 / 再下滑 |
| 枚举名 | **待定**：我建议 `chromeToggle`（名字描述行为）；PRD 现写 `focusPull`（名字暗示下拉手势，若三指下滑被否，这个名字就名不副实） |

## D. T3 标注用语（许清楚，改措辞防误读）

标注写「**径向 clip-path 裁剪**」，**禁止**写成"渐变染色"或"tint 渐变"——后者会诱导实现去插值材质参数。T3 的色带层是**纯色渐变、不是玻璃**；玻璃元素在 T3 期间 tint 不变、只做 opacity。

## E. 新增小节：改名检查清单（PM 建议，我同意成节）

每次功能改名，必须逐条过：

1. **这个动效的隐喻还成立吗？**（T2 就是靠这条被发现的：⑤ 从"多源"变"多版本"后，"换书脊"指向另一本书，隐喻失效）
2. **宿主链路是否一起搬了？**（T5 从"书源切换成功"搬到"换一份文件成功"，只改名不搬宿主 = 更隐蔽的规避表述）
3. **ID 中文名与界面文案是否踩禁词？**（书源/换源/搜书/找书/书库/全网/免费/海量/聚合/破解/解锁/去广告/纯净版/无限/精校/全本/全集/完结/补全/完整版）
4. **枚举名是否描述的是旧行为？**（`spineSwap`/`focusPull` 这类名字会在代码里长期误导人）
5. **旧名是否已留痕？**（`git log`、旧设计稿、商店截图都会被翻出来 → 首次即正确 > 事后改名）
6. **关闭态是否仍描述得通？**（改名后关闭态常常变得不可执行，如"书脊与卡片 rect 全程不动"在版本层翻片下才成立）
