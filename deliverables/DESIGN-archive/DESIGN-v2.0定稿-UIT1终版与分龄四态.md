## A. UIT1 终版：`chromeToggle`，唯一入口点按正文中央

| 项 | 结论 |
|---|---|
| 行为 | chrome 显隐（唯一行为）；专注态 = chrome 收起，不是独立概念 |
| 入口 | **唯一：点按正文中央**。阅读器内不再有彩蛋之外的手势入口 |
| 自动恢复 | **不做**（省掉 6 秒定时器；避免"用户正专注时 chrome 自己弹出"这种最粗暴的打断） |
| 三指下滑 | **永久不做**，不是暂缓 |

**两条不能翻案的理由（PM 补强，比"暂缓"更强的表述）**：
1. 三指在 iOS 上是**系统保留手势**（轻扫撤销、双击、辅助功能拖移），系统优先级高于 App——**用户开了辅助功能，我们的三指手势直接失灵且无提示，这属于无障碍缺陷，不是体验取舍**。
2. 撤掉后路径不封闭：仿真模式下退出 = 点中央 → 顶栏返回，**路径存在**。

## B. 【作废】小字号自动高对比整节——字号只有 19/20/21 三档

PM 确认 FR-009 收敛为三档（12pt 长读不可用；32pt 一行只剩约 11 字，行长崩）。**因此 12–17pt 区间不存在**：
- 滑杆上的 16×16 小锁、说明行、"自动提亮"这套 UI **全部不做**；
- "切回 ≥18pt 恢复默认档、无动画"的分支 **删除**——它描述的是一个不存在的状态；
- 三档全部 ≥18pt，均属 WCAG"大字"，默认 #8A8A8A（5.4:1）**始终合规**，无需任何自动切换。

**保留理由（PM 原话，写进注释）**：**做出来的功能如果走不到，比没做更糟**——开发会照图实现，然后用户永远碰不到它。

## C. 分龄四态 + 两种受限态必须视觉可分

四态：`.adultConfirmed` / `.minorConfirmed` / `.provisionalMinor` / `.unverified`（industry 裁定）。

| 态 | 行为 | 视觉 |
|---|---|---|
| `.adultConfirmed` | 全功能 | 普通模式 |
| `.minorConfirmed` | 未成年模式：本地只读、宵禁 22:00–6:00、时长限制、Tab 3 项 | **宵禁样式**：顶部 41pt 时长条 + 时段限制态（详见 ⑪） |
| `.provisionalMinor` | 年龄拿不到 → 保守进入未成年模式；**允许自动重试并静默切换**到 `.minorConfirmed` 或 `.adultConfirmed` | 同未成年模式，但顶部条右侧加一行 caption「正在确认年龄…」，**不阻断操作** |
| `.unverified` | **不套未成年人模式**：本地能力全开、无宵禁与时长限制、无联网能力 | **仅一条常驻非阻断提示条**（28pt，`--ink-raised` 纯色 + 1pt 描边，非玻璃）：文案「完善年龄信息，以获得完整的阅读体验」+ 右侧文字按钮「完善」→ 回到 ⓪ 页 |

**关键区分（PM 强调）**：两态措辞必须不同——`.unverified` 是"完善年龄信息"，**不是"退出未成年模式"**；视觉上未验证态**没有宵禁样式、没有时长条**。否则用户分不清"我被限制了"还是"出故障了"。
**页面归属**：`.unverified` 不新增页面，作为普通模式下的**常驻提示条状态**（出现在 ①③ 等页顶部）；`.provisionalMinor` 复用 ⑪ 页 + 一行 caption（**是否要独立页，待 PM 定**）。

## E. 判据清单（新增三条，规范开头）

1. **合规不是只能删功能**：很多时候功能是干净的，有问题的是它承载的对象。「位置对齐」就是这么活下来的——它本身合法，只是原来挂在有风险的对象上。**遇到"要不要砍"，先问能不能换一个合法对象。**
2. **彩蛋的可关闭性不由它多有趣决定，由它有没有等价路径决定**（EGG1 纯装饰／EGG2→视图切换按钮／EGG4→菜单加书签／EGG5→菜单换文件；缺一则降为功能型，逻辑必须保留）。
3. **关动效只能减掉动画，不能减掉能力。**
（原有三条：禁用态暗示有朝一日会开／30 秒淡出就是 30 秒绕过／数字算出来就是倒计时器。）

## F. T3 做法确认（架构问）

**确认并已写入规范**：色带层用**纯色渐变层**（`CAGradientLayer` 或自绘，**不是玻璃**），玻璃元素在 T3 期间 **tint 不变、只做 opacity**。即"观感上的颜色变化由色带层承担，玻璃只负责淡入淡出"。
标注用语：**「径向 clip-path 裁剪」**，禁用"渐变染色 / tint 渐变"（后者会诱导实现去插值材质）。
机制理由（架构提供，写进注释）：**材质参数一变，系统要重新采样并重算整个 backdrop，是全屏级操作；而 opacity / transform 走图层合成，成本几乎为零。**

## H. EGG5 耦合注记（架构提醒）

> **EGG5 的 shake 注册与 3 次/分限流是同一条开关，不得分别修改。**

关闭态不注册 `CoreMotion`（摇动彻底无响应、限流一并停跑）；将来若重新启用，**限流必须同时恢复**——否则"看不见但还在耗电"或"关动效反而无限触发"。
**注册范围扩至全部非 `.adultConfirmed` 态**（架构建议，我采纳）：非成年态即使摇出面板，面板内容来自在线能力而该态本无在线能力 → 摇出空面板比摇不动更像 bug。

## I. 反向验收条件（单列小节，PM 建议）

| 条件（出现即判不合格） |

| 只有摇一摇能换文件（彩蛋承担主路径） |

| 非成年态出现联网能力或宵禁样式缺失/多余 |
