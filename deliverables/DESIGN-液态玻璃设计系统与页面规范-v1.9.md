## 0. 读法与判据

### 0.1 三条使用顺序

1. **先过判据**（§0.2 八条）→ 2. **再用禁词表兜底**（§10）→ 3. 交付稿自带「文案自查」一节。
**不要反过来。** 词表是滞后产物，只能收录已经踩过的词；能被判据捞出来的词，才是还没踩的坑。

### 0.2 判据清单（后人要推翻的是一条判据，不是一个设计决定）

| # | 判据 | 出处 |
|---|---|---|
| 1 | **合规不是只能删功能。** 很多时候功能是干净的，有问题的是它承载的对象——先问能不能换一个合法对象 | 合规评审 |
| 2 | **禁用态暗示"有朝一日会开"。** 永不可用的能力→不出现；可被家长配置的能力→放家长设置 | 合规评审 |
| 3 | **30 秒淡出就是 30 秒绕过。** 任何动效不得延迟"限制生效"的呈现 | 合规评审 |
| 4 | **数字只要算出来就是倒计时器**，刷新频率不改变性质 | 合规评审 |
| 5 | **彩蛋的可关闭性不由它多有趣决定，由它有没有等价路径决定** | 架构评审 |
| 6 | **关动效只能减掉动画，不能减掉能力** | 本文档 |
| 7 | **做出来但走不到的功能，比没做更糟**（条件为永假的分支必须整条删除，不写"条件生效"） | 产品 |
| 8 | **名字要描述行为，不描述来源或意象**（枚举名同理） | 架构评审 |

### 0.3 两处例外与边界

- **「我 → 高级 → 书源（实验）」入口内部**是唯一例外：须**如实**描述真实功能，但不得营销化。把"书源"改叫"实验功能"构成隐瞒功能——**主链路零禁词 + 实验入口内如实**才是解法，切忌反向清洗。
- **反向禁词**（不宣称完整、而是暗示"我们持有"）比正向禁词更难被词表抓到：`全文索引 / 全文检索` 裸用像"我们持有全文"，**引用时必须带限定**——「仅对本地导入文件建立索引；在线内容不落盘、不建索引」。

### 1.3 阅读排版常量（不可妥协）

正文 PingFang SC Regular；章标题 22/32 Semibold；**段间距 12pt**（段前 12、段后 0），**连续空段折叠为 1**；首行缩进默认 0（开启 = 2×字号）；左右边距 **20pt**（16/20/24 可选）；上 = 导航栏底 +24pt，下 = 28pt + 安全区；**左对齐，明确不做两端对齐**。
**行盒的推导式以 PRD 为唯一真源（D-31）**：**行盒 = 字号 × 倍数**（PRD §排版基线：19×1.70≈32 / **20×1.75＝35** / 21×1.85≈39）；开发用 `minLineHeight = maxLineHeight`。**本规范不再另立行盒数值、也不写「不给倍数自行计算」**——PRD 较新且更细（多出「用户可调行距」这一维），另立一套推导口径就等于多出一个真源，而**第二套真源正是行盒算错 3pt 的成因**。
图片占位固定 **3:4、aspect-fill**，长图点击进全屏原图；图注 caption 11 居中、上下各 8pt；图与段间 16pt。
（后两条是**跨版本 diff 归零项**，非审美项：A 版有图注、B 版没有时，图后首段位置必然差一截。）

4/8 基准：2 / 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64。页面边距 20（阅读页 20，可调 0–40）；卡片内距 16；卡距 12；组距 32；列表行高 56；顶栏 44；TabBar 49 + 安全区；主按钮 50。书城 2 列 gap 12 封面 3:4；书架网格 3 列 gap 16。

### 1.5 圆角

容器圆角（几何圆）：r-8 图标底、r-12 输入/标签、r-16 缩略图。
连续曲率（squircle）：c20 卡片、c26 大卡/浮层、c32 模态/浮层容器。iOS `.continuous`；CSS 优先 `corner-shape: squircle`，降级 `border-radius ×1.12`。玻璃一律连续曲率。**蜜桃汽水整体 +4**（c24/c30/c36）。

## 2. Liquid Glass 材质

### 2.1 定位说明（先读，否则会误用）

**本文档的视觉配方用于 HTML 原型与设计稿表达。** 原生实现走系统 `glassEffect`，其内部结构不开放——**`blur` / `saturate` / `brightness` / 色散强度均无对外入口**，原生只能控制 **tint / `.interactive()` / 形状 / `strokeBorder`**。
**验收口径**：原型按 CSS 验收（可像素比对）；**原生按观感等价验收，不得要求与原型像素级一致**。

### 2.2 玻璃强度 L1 / L2 / L3（不是"材质档"，不是 Thin/Regular/Thick）

> **护栏句（写进代码注释）**：L1/L2/L3 的差异**仅为 tint 强度**，不存在材质参数切换。`.regular` / `.identity` 是 `Glass` 变体，`interactive` 是交互开关，**两者都不是强度档**。**禁止在玻璃视图树内使用 `.thinMaterial` / `.regularMaterial` / `.thickMaterial`**（iOS 15 旧材质系统，与 Liquid Glass 是两套东西，混用双损）。

| 档 | 原生实现 | tint | 典型 |
|---|---|---|---|
| L1 | `.glassEffect(.regular.tint(t), in: shape)` | 0.14 | 搜索胶囊、吸底操作条、Toast |
| L2 | 同上 | 0.20 | 继续阅读卡、分段控件、成就卡 |
| L3 | 同上 | 0.28 | 「换一个版本」面板、阅读设置浮层 |

**`.clear` 暂不设档**（待真机看过"浮层压在大幅插图之上"再定），避免规范里多一个无场景的档位。

### 2.3 `interactive` 与档位正交（不写进档位表）

| 维度 | 决定什么 | 由谁决定 |
|---|---|---|
| tint 0.14 / 0.20 / 0.28 | 观感档位 | 设计（背景复杂度 + 内容权重） |
| `.interactive()` | 是否可点击（按压回弹） | **控件性质**，与档位无关 |

| 控件 | 档 | interactive |
|---|---|---|
| 搜索胶囊、吸底操作条按钮、TabBar 内自定义控件 | L1 | 是 |
| **Toast、只读提示条** | L1 | **否** |
| 继续阅读卡、分段控件、成就卡、主题预览卡 | L2 | 是 |
| 静态信息容器（模式说明组） | L2 | 否 |
| 面板/浮层**容器本身** | L3 | **否**（内部按钮各自加） |

**反例会出事**：Toast 不可点，却因套了 L1 带上按压回弹 → **骗用户去点**，且 review 几乎发现不了。

### 2.4 边缘与描边（两条规则）

1. **原生玻璃态不加描边**：系统自带边缘高光与反射，再叠 1pt 会成双线且曲率不一致，观感显脏。
2. **降级态必须 1pt 描边**（纯色降级、Reduce Transparency、性能降级）。
3. 需更强边界定义时：**加深 tint + 加阴影**——阴影给"悬浮于内容之上"的分层感（Liquid Glass 语义），描边只给"贴纸"感。

### 2.5 四态收起（P0 验收项）

| 状态 | 玻璃表现 |
|---|---|
| 静止 | 全参数 |
| **仿真翻页动画期间 / 滚动中** | `backdrop-filter: none` + `rgba(surface,.92)` 纯色 + **1pt 描边**（此时属降级态），动画结束 120ms 淡回 |
| 转场 380ms 内 | 仅 opacity，材质冻结 |
| 手势跟手（UIT1 / EGG2 / EGG4） | 同纯色；结束后 120ms 淡回 |

**通用规则（Level 高）**：**所有动效期间禁止插值材质参数（tint / blur / refraction），只允许 opacity 与 transform。**
机制理由：材质参数一变，系统要重新采样并重算整个 backdrop，是**全屏级操作**；opacity/transform 走图层合成，成本几乎为零。**这不是"设计节制"，是"避免在动效帧里插入全屏重算"——定性决定它能不能被打折。**

### 2.6 玻璃预算（硬约束）

一屏 **1–2 处**玻璃浮层；**正文区永远零玻璃、零阴影、零 scrim、零装饰字**。

**计数口径（D-19，照抄原文）**：
> D-19 全局 TabBar 不计入「一屏 1–2 处玻璃浮层」的配额。
>
> 理由：TabBar 是常驻导航容器，不是浮层。若把 TabBar 计入该配额，则全局五个 Tab 页全部天然违规，规则失去判别力——一条会把所有页面都判死的规则，不是规则，是噪声。计数对象应当是「同一屏内的浮层玻璃」。

**计数对象的四条界定（配 D-19 使用）**：
1. **排除必须逐个具名，不接受类别推定**：下列三个对象**不计入**浮层配额——**① 全局 TabBar（`#tabbar`）；② ④ 页顶栏与底部阅读工具条；③ 屏外调试坞（原型 `.dock`，在 `<aside>` 内、手机屏外）**。**排除只作用于「浮层配额」这一维；单块面积上限按各自实测独立成立**——① TabBar 实测 341×64＝21,824pt²＝6.5%，**即使计入面积也不超 30%**；② ④ 页顶栏与阅读工具条按实测独立判；**只有 ③ 整体不适用产品屏红线**（理由见第 4 条）。**新增的导航类元素默认计入**，不得以"它属于导航容器"为由自行排除——**排除写成类，就成了后门**：规则一旦可以按类目自行豁免，就等于没有边界。**TabBar 被排除的理由是"它是常驻导航容器、不是浮层"，不是"它小"**（实测 341×64＝21,824pt²＝6.5%，**即使计入面积也不超 30%**——计数与面积是两件事，别拿尺寸去论证归类）。
2. **数同时可见的，不数 DOM 节点**：同屏内互斥显隐的同功能容器按 1 处计。例：③ 书架页 `shelfSeg`（网格视图，104×36＝3,740pt²＝1.1%）与 `shelfSeg2`（书脊视图，**默认态隐藏，0×0**）由 `data-shelfmode` 互斥——`.phone[data-shelfmode="spine"] .shelf-scroll{display:none}`，**同屏任意时刻只可见 1 处分段控件**，不得按 DOM 节点数累加成 2 处。
3. **同一容器内的玻璃子件不重复计数**：分段控件的选中态底色、图标玻璃描边等不计为新的一处。
4. **屏外元素不计入（判定对象＝产品屏内）**：原型调试坞 `.dock` 位于 `<aside>` 内、**手机屏外**（312×392＝122,304pt²＝36.5%），**不计入浮层配额，也不计入单块面积约束**——**用产品屏的面积红线去判一个不在产品屏里的对象，是判错了对象**；它的 36.5% 不是一个违规事实。

**容器白名单（玻璃容器逐个对应原型实现）—— 分两张表，两类对象两把尺子**：

> **拆表理由（2026-10-28，D-38）**：**两类约束对象不同**。**表 A = 底部／浮层容器类**（浮在内容之上、从屏幕下缘升起的一整块），约束的是**高度**（≤ 屏高 75% ＋ 内部滚动）；**表 B = 屏内卡片类**（内容流里的一块，不脱离正文），约束的是**单块面积**（≤ 屏面积 30%）。**混在一张表里必然被混用——本次的口径漂移正是这么来的**：验收方按总册 06 章的「单块玻璃 ≤ 30%」去量四块底部 sheet，量出 46.8% / 67.4%×3 四处"超限"，而这四块在新口径下**全部合规**。**尺子用错了对象，量出来的超限不是违规**。故本节把表拆开：**查底部 sheet 去表 A，查屏内卡片去表 B**；两张表**不可互相引用对方的尺子**。

**白名单容器通用约束（两条）**：
1. **`opacity` 属性恒为 1；背景色 alpha 允许 < 1**——这两件事必须分开说，混成一条就会同时错两处：**① `opacity` 属性不得 < 1**：那会把容器内的**内容**（正文、文字、控件）一起变半透明，文字对比度随即不可控（§2.7 的阈值一并失效）；正确做法是**给背景色设 alpha、内容层保持 100% 不透明**。**② 背景色 alpha 允许 < 1**（§2.2 的 L1 / L2 / L3 tint 0.14 / 0.20 / 0.28 本身就是半透明）：**半透明是玻璃可折射的前提**，把 alpha < 1 一并禁掉，等于**禁止一切玻璃**，与 L1–L3 的定位直接矛盾——**一条把规则适用对象定成它必然违反的对象的规则，等于没有规则**。降级态（§2.5）的"纯色底"按 `rgba(surface,.92)` + 1pt 描边执行，**其对比度仍按 §2.7 不放宽**。
2. **信息承载类（`contactSheet`）的内容完整性优先于面积上限**——面积上限约束的是**视觉成本**，不是信息完整性；**删内容去迁就面积上限，是本项目最不该出现的操作**。处置方式是**限高 + 内部滚动**。

**底部 sheet 四块的视觉归属（2026-10-28 已裁定，见台账 D-38）**：《原型验收记录 v3》第 12 项把四块底部面板判为「单块玻璃超 30%」——**该判据的尺子用错了对象**：单块 30% 是给**屏内卡片**写的，套到 353 宽的底部 sheet 上等价于**高度 ≤ 284.6pt ＝ 屏高 33.4%**，与"底部 sheet"这个形态本身不相容。**先辨"该不该是玻璃"（视觉归属），再谈"该怎么处置"（面积）**——顺序反了，就是拿面积数字去倒推一个还没做的美学决定。**本轮已裁：四块全部维持玻璃 L3，本期不改原型。**

**为什么本期不改原型（新口径下没有触发条件）**：**本期四块在新口径（底部 sheet 走高度 ≤ 屏高 75%＝639pt ＋ 内部滚动）下全部合规**——实测高度 444pt / 639pt / 639pt / 639pt 均 ≤ 639pt。**"超限"这个触发条件根本不存在；没有超限就不启动材质变更。** 上一轮判定的「四处超 30%」是**尺子用错对象**的产物、不是违规事实；**为一个不存在的问题付出差异化代价，是最贵的错误**。

**保留并强化的那条**：`setSheet` **不必**压到 ≤ 284.6pt——那等于把排版设置砍成 8 行、必须重度滚动；**排版设置是高频操作，为省面积牺牲它不值**。本条不因裁定而松绑，反而更明确：**新口径下 `setSheet` 444pt 合法，不需要任何面积妥协。**

**待评估项（触发条件：POC-2 真机判据产出之后；本期不改）**：`contactSheet` / `srcSheet` 改纯色 `.glass-solid`。两条美学理由（法定告知文书用制度语气、密集文字列表压可读性）**成立且保留**，但**不能靠旧尺子触发**——新口径下二者均合规，改纯色只在**真机测出玻璃大面积模糊的 GPU 拐点、或实测对比度不达标 §2.7** 时才值得做，届时由 POC-2 的真机判据决定。**不提前改，也不以未验证的假设去换未验证的风险。** 触发前二者**仍在玻璃白名单表 A 内**，四块 L3 计数不变。

**已移出白名单（不计入玻璃）**：`quoteModal`（EGG5 随机书摘卡）→ **纯色 `glass-solid`，非玻璃**。理由：① 它压在阅读页**正文正中**（`top:50%` + `translateY(-50%)`），覆盖正文可见区，违反 §2.6「玻璃浮层不得覆盖正文可见区」；② §2.6 只给了「正文整体上移让位」这一个让位机制，**未为居中浮层定义让位**；③ EGG5 是彩蛋，彩蛋不应遮挡阅读（DESIGN-archive v1.2 早有同向裁定）。原型已同步去掉 `backdrop-filter`，**类名上的 `glass glass-l3` 声明也已摘掉**（现为 `quote-modal glass-solid`）——类名会骗人：未来的验收脚本按类名统计，就会把它算进 L3 玻璃。

**玻璃判定的同源判据（与 §7.2b 同源）**：统计玻璃、或判「未使用玻璃」时，**必须单独取值 `backdrop-filter` 属性是否存在**，不得只靠 `transition` / `animation` 时长推断——**`backdrop-filter` 不产生可采样的时长**，过渡维度全为 0 的元素仍可能带全屏模糊（宵禁拦截页正是这一类）。**穷举证明的维度必须写全：漏掉一维，该维就是盲区**（D-23）。

**底部 sheet 类容器的统一口径（四个 sheet 一体）**：

> **底部 sheet 类容器（阅读设置 / 换一个版本 / 年龄状态 / 版权声明与投诉）**：高度上限 **≤ 屏高 75%（639pt）**，**超出部分内部滚动**，不外溢、不裁切、不删内容。**信息承载类（`contactSheet`）与内容超 640pt 者的内容完整性优先于面积上限**——面积上限约束的是视觉成本，不是信息完整性；**删内容去迁就面积上限，是本项目最不该出现的操作**。单块玻璃 30% 兜底**只适用于屏内卡片类**（如发现页 `.rec-card`，实测 20.1% 合规）。

**面积上限（分两类，别混用）**：
- **屏内卡片类**：单块玻璃 ≤ 屏面积 **30%**。基准视口 **393×852＝334,836pt²**，30% ＝ **100,451pt²**。**按屏面积比例计算，不同机型以实际屏面积为基准**——30% 是**比例**不是绝对像素数，393×852 仅为基准视口，换机型时**不得沿用 100,451pt² 这个绝对值**。实测最大屏内玻璃 = 发现页 `.rec-card` 333×202＝67,204pt²＝**20.1%** ✓。超限 → **降一档材质或改纯色**（**但降一档并不改变被约束的量**，见下）。
- **底部 sheet 类**：走上面的**高度口径**（≤ 屏高 75%＝639pt + 内部滚动），**不适用单块 30% 面积兜底**。**理由可量化**：30% 面积兜底套到 353 宽的底部 sheet 上，等价于**高度 ≤ 284.6pt ＝ 屏高 33.4%**——**一条要求底部 sheet 不超过三分之一屏高的规则，与"底部 sheet"这个形态本身不相容**（底部 sheet 的定义就是占屏下 1/3～3/4）。这条 30% 是为**屏内卡片**写的，**尺子用错了对象**。实测四块 sheet 353×444（46.8%）与 353×639（67.4%）在高度口径下均合规。
- **不得全屏**：单块玻璃不得达到全屏（宵禁拦截页已定为静态遮罩，理由见 §7.2b）。

**两处必须说清的"不等于"**：
1. **降档 ≠ 解决面积超限**。总册**旧版**那句处置口径「超限降一档材质或改纯色」（**该句已按 D-38 从总册删除**）里，**"降一档"这一半是无效的**：353×639 从 L3 降到 L1 仍是 353×639＝225,567pt²＝67.4%，面积一项分毫未动。**只有"改纯色"能让面积项归零**（纯色面板不再计入玻璃面积）。规矩写错半句，执行者就会以为自己已经合规了。
2. **改纯色 ≠ 唯一出路**。它同时砍掉液态玻璃这个差异化抓手，而玻璃观感的 GPU 拐点还挂在 POC-2 未验（POC-2 正在测"玻璃大面积模糊的 GPU 开销拐点"）——**用未验证的假设去换未验证的风险，是最差的交易**。**顺序不能反：先定"这块面板该不该是玻璃"（视觉归属），再谈"该不该降档"（面积处置）**；顺序反了，就是拿面积数字去倒推一个还没做的美学决定。

**总册已按 D-38 同步为双口径（口径已统一，不是两套数并存）**：总册 06 章现为**双口径**——**屏内卡片类**单块玻璃 ≤ 屏面积 30% ＝ **100,451pt²**（基准视口 393×852＝334,836pt²；**不同机型按实际屏面积计算**）；**底部 sheet 类**走 ≤ 屏高 75%（639pt）＋ 内部滚动，并明确「**不适用单块 30% 面积兜底**」。旧值「**约 103,000pt²**」是按 **375×915** 视口估算（343,125×0.3＝102,938）的**不同源**数字，**已从总册删除**；那句「超限降一档材质或改纯色」的处置口径也已一并删除（理由见上「降档 ≠ 解决面积超限」——**降一档不改变被约束的量**）。**口径统一的方向是「以高度口径为准、总册同步」，不是「两种口径并存」**——两份文档对同一件事说两套数是**漂移**，只能有一份有效。

**同一屏浮层玻璃超过 2 处时的降档顺序（先合并 → 再降层级 → 仍超则移出该屏）**：
1. **先合并**：同一屏同类控件归并为一处（同一屏出现两处分段控件时，合成 1 个玻璃容器；③ 书架页那两处本就因互斥显隐只算 1 处，见计数对象第 2 条）；
2. **再降层级**：L2 → L1（tint 0.20 → 0.14）；
3. **仍超则移出该屏**：改纯色 + 1pt 描边，或移出该屏。

**玻璃浮层不得覆盖正文可见区**——浮层出现时正文整体**上移让位，上移量 = 该浮层实际高度 + 24pt 间距**（**不再写死 320pt**：sheet 高度口径已从 ≤320pt 改为 ≤639pt，写死 320pt 会让 640pt 的 sheet 仍然压在正文上）；**不叠遮罩、不变暗**（scrim 会压低正文对比度，与夜航 5.4:1 门槛自相矛盾）。上移后露出的顶部用**主题底色 + 1pt 细线**填充，不用模糊。

### 2.7 可读性

玻璃上文字 ≥4.5:1（<17pt）/ ≥3:1（≥17pt 且 600）；文字层必带 `text-shadow: 0 1pt 2pt rgba(0,0,0,.30)`；不达标 tint ×1.2；仍不达标改纯色底。

### 2.8 验收规定

**玻璃观感必须真机验收。** `.regular` / 澄清档在模拟器上折射几乎不渲染，看起来扁平干净，对比度不足与边缘消失问题**在模拟器上完全看不出来**——**禁止用模拟器截图做玻璃终审**。真机基准由架构 POC-2 提供（浅色 / 深色 / 图文混排三种底）。

**EGG1 不拆 case 的原因**：枚举一分裂，"未登记即构建失败"的检查就失效——同一语义有多个 case 时，登记者随手选一个即可绕过。
**EGG5 耦合注记**：`shake` 注册与 3 次/分限流是**同一条开关，不得分别修改**；重新启用时限流必须同时恢复（否则"看不见但还在耗电"或"关动效反而无限触发"）。

**EGG5 改写理由（2026-10-28 裁定，以原型为准改规范）**：原型 `MotionRegistry` 与总册 §13 均为「**摇一摇书摘** → 随机书摘卡（高 ≤280pt）」，DESIGN 原写「摇一摇唤出『换一个版本』面板（L3）」是**三方对照里唯一漂移的一方**——两对一，规范改。**不改原型。** 书摘卡压在阅读页正文正中，按 §2.6「玻璃浮层不得覆盖正文可见区」与「彩蛋不遮挡阅读」，**改为纯色 `glass-solid`（非玻璃）**；原型已同步去掉 `backdrop-filter`，**类名上的 `glass glass-l3` 声明也已摘掉**（现为 `quote-modal glass-solid`；类名会骗人：验收脚本按类名统计就会把它算进 L3 玻璃）。英文 ID `shakePanel` 保留——它仍描述"摇动 → 面板/卡片"，改名要另走 §4.5 改名检查清单。

**EGG5 等价路径 —— 如实留痕（待办，不得以不存在的菜单充数）**：§4.1 关闭态规则要求彩蛋「当且仅当有非手势等价路径」才可在关闭态注销逻辑。EGG5 改为书摘卡后，**原型内不存在「菜单」这一 UI 形态——没有任何一张菜单**：`chrome` 作为 CSS 类名前缀在原型中有 **23 行（词频 27 次）**命中，指的是**阅读页 chrome 层** ＝ 顶栏 ＋ 底部工具条。④ 页顶栏的**齿轮按钮** `#readerMore` 是**阅读设置按钮**（`aria-label`「阅读设置」、行为 `openSheet('setSheet')`；**图标为齿轮、非「⋯」三点溢出——D-49 已改**，理由：**图形是对外承诺**，语义与图形不符时该改的是图形）——**它是一颗按钮，不是一张菜单**，其上没有任何菜单项。**原型没有任何「菜单」形态——④ 页只有顶栏按钮 ＋ 底部薄玻璃工具条两项，没有第三种东西**。书摘卡当前**仅「连点章节标题 3 次」模拟入口**（真机为 CoreMotion 加速度阈值）——**这是彩蛋自己的模拟入口，不构成一条独立可达的等价路径**。**两件事不可混为一谈**：**「换一个版本」的主路径是有的**——④ 页底部阅读工具条第 4 项「**换一个版本**」（`data-rtool="source"` → `openSheet('srcSheet')`），它真的打开「换一个版本」面板；**缺的是「书摘卡自己的独立可达等价路径」**——前者已具备，后者仍待补。故 **EGG5 目前不满足"当且仅当"的条件**，其关闭态归属**待裁定**；在裁定前，§4.1 表内「彩蛋 → 摇动无响应，限流一并停跑」继续有效。**不得为凑齐路径，在规范里写一个原型中不存在的菜单。**
**三个被否决的方案（不得重议）**：三指下滑（系统保留手势，开辅助功能时失灵且无提示=无障碍缺陷）｜新增第二入口（点中央已足够，加手势只增加冲突面）｜6 秒自动恢复（专注时工具条自弹是最粗暴打断，且要引一个定时器与功耗指标冲突）。**若日后确需专用入口，选双击正文中央，不得再议三指。**
**⚠ 方向澄清（勿与原型混为一谈）**：原型 `setChrome(on)` 内的 6 秒定时器（`setTimeout(function () { readerEl.classList.add('chrome-off'); }, 6000)`）是**自动收起**，与本条否决的**自动弹出**方向相反——**两者不是同一件事，本条的否决不涉及原型那个收起定时器**；原型实现维持原样，**该否决条目不得删除**。

### 4.2 关闭态语义（「不播动画路径」，不是时长 0）

`.duration(0)` 是**错误实现**（仍会画一帧旧 frame）。正确为 `withTransaction(Transaction(animation: nil))` + `AnyTransition.identity` + 彩蛋不创建视图。
**验收**：首帧与末帧**逐帧 diff = 0、无中间帧**（不检查 `duration == 0`）。

### 4.3 T1 实现要点（两个最容易错的坑）

- **书脊轴**：`CATransform3D` 无 transform-origin → `layer.anchorPoint = (0, 0.5)` 并**同步补偿 `layer.position`**（不补偿图层会跳位，最易错的一步）；`perspective 1200` → `m34 = -1/1200`。
- **层序（单层 overlay）**：z0 书架**位图快照**（"静态"= 一张位图，不是实时视图，否则书架玻璃仍在渲染 → 抢帧）｜z1 封面快照容器（内部子层 z3→z0）｜z2 正文 opacity delay 140｜z3 返回按钮玻璃 delay 260（全页仅此 1 处玻璃）。
- 关闭态：不创建 z0/z1，z2 与 z3 **同帧**出现。
- `380ms (pending POC-1, +40ms reserved)`。

### 4.4 T2 的性能注记（连代价一起写）

> T2 曾用 `blur 0→3→0`，260ms 内约 15 帧 `CIFilter` 重算，**已评估为不必要开销后移除**。重新引入需重测 NFR-06（30 分钟温升 ≤4℃）。

### 4.5 动效注册表与命名

唯一入口 `Motion.play(_ id: MotionID)`；编译期扫描裸调 `withAnimation(` 直接报错；13 个 case 不加第 14 个。
**改名检查清单（每次功能改名逐条过）**：
1. 这个动效的**隐喻**还成立吗？2. **宿主链路**是否一起搬了？3. 是否踩禁词？4. **枚举名是否描述旧行为**？5. **旧名是否留痕**（`git log`、`MotionID` 注释、**测试用例名**、**Fastlane 截图文件名**——后三处最易漏，且截图文件名会进提审材料）？6. **改名后关闭态是否仍描述得通**？
> 第 6 条反例：T2 改"版本层翻片"后，关闭态原句"书脊与卡片 rect 全程不动"只在旧语义下成立；新语义下书脊本就不动 → 该句变成对不存在的状态做断言。**后果是测试去验一个不存在的状态，而它一直是绿的，直到真机出问题。**

**`.unverified` 不得写「在线功能不可用」**：B 版发行版里**没有任何"在线功能"可被禁用**，写这句会让用户以为我们本来有在线内容能力，与对外声明直接冲突。**声明一个不存在的限制，和声明一个不存在的内容一样，都是虚假陈述，只是方向相反。**
代价是文案变"轻"——所以**必须保住两句常驻提示**（「如本设备由未成年人使用，请开启未成年人模式」+ 路径说明），否则这一态看起来只是句无所谓的话，用户不会去处理。**轻文案配足引导，是能删掉那句假话的前提。**

**两条实现约束（影响三态组件）**：
1. **状态条文案必须从状态矩阵派生**，不得在视图层写 `if state == .xxx` 各自拼字符串。矩阵字段至少含：状态条主文案 / caption / 空态动作词。这样**禁词检查只需对矩阵做一次**，改口径只改矩阵。
2. **路径文案取系统本地化字符串运行时拼接，取不到时整句隐藏**——不 fallback 到英文或中文、不自行翻译。**"写错的路径比不写更糟"**：用户照着找一个不存在的菜单，会认为是我们编的。降级方向必须是"少说"，不能是"猜一句"。


**内部命名改 `.ageUnresolved` 的原因**：内部名也会出现在证据链里——叫"未成年"却从未确认过，会在文书里造成误导。

**两态区分信号 = 行为差异，不是外观**：`.ageUnresolved` **有时段限制（22:00–6:00 拦截态）**，`.unverified` 没有。**按钮是外观，时段限制是真行为**——用行为差异当信号更不会骗人。

**`.unverified` 的路径是文字，不是入口**：
- 一行**纯文字**路径「设置 › Apple 账户 › 个人信息 › App 年龄段」，**可长按复制、不折叠不隐藏**（不得做成"点击展开"）；
- 视觉为说明文字（`--ink-text-2`、13pt），**不做链接色、不做胶囊、不带下划线**——一旦长得像可点，就破了"它是解释不是出路"；
- **不做按钮、不做弹层**：`openSettingsURLString` 打开的是本 App 设置页，而我们没有 settings bundle 项，用户会点进空白页——比没有按钮更糟（用户会认为 App 坏了）；deep-link 到系统「App 年龄段」也无公开 URL scheme。

**`.ageUnresolved` 三条硬要求**：caption **常驻可读**（不用 toast，toast 会消失）；**不做 spinner、不做循环动画**；**不自动降级**——重试降频但不清空状态，界面持续显示未确认，重试成功当场恢复阅读。
> 「等 7 天就免宵禁」与我们已否掉的 C 方案是同一条可等待绕过路径，而且对孩子更简单（断网一周即可）。**"临时"不设期限，因为它本来就不是靠时间解决的状态。**

**`.ageUnresolved` 与 `.unverified` 的空书架必须画成"可导入"**，不得画成锁定态（允许导入是这两态能被接受的前提，否则离线首启的成年用户面对空书架无法添加任何书）。**两态内必须存在可进入的导入入口**（在页面内，不在拦截页里、拦截页不给按钮）。

> **同一状态只有一句文案。** 状态横幅与宵禁拦截页必须逐字一致（本次因两处不一致被合规逐字比对抓出，属真实缺陷）。
> **主文案给动作，不给被动承诺**：「完善后即可继续阅读」是动作路径；「网络可用时将自动确认」是被动承诺，用户读完不知道要做什么会干等——它只能作补充小字，不能作主文案。
> **「未成年人保护已生效」不是修辞**：它是宵禁正当性的支点，删了它，"为什么在 22 点拦你"就没有解释，用户会当 bug 报。

### 7.2 宵禁拦截页（三态共用）——禁止项

主文案：「**年龄信息未完善 · 未成年人保护已生效，完善后即可继续阅读**」
下方文字路径：设置 › Apple 账户 › 个人信息 › App 年龄段

**禁止（写成禁止项，不是建议）**：出现"退出 / 解锁 / 切换 / 跳过 / 解除"任何字样；出现**任何可点击按钮**（含"去设置"）；写任何具体时间点。
**它是解释，不是出路。**（本条为高危项：最容易被"提升体验"改成「去设置」按钮，那就是我们删过两次的解锁路标第三次复活。）
**验收**：网络可用且重试成功时，**宵禁必须立即解除、拦截页当场消失并恢复阅读**，不得提示"请重新进入"——否则用户会觉得"我完善了但没生效"，比不给提示更糟。

5. 宵禁拦截页 → 与第 2 条逐字一致

**逐字比对比一对一映射表有用的原因**：真正会出事的地方不是"漏扫"，而是**三态文案在流转中被改写一句**——映射表挡不住改写，逐字比对能。本次就是靠贴出文本被合规逐字比对发现"横幅与拦截页两句不一致"，否则它会一路走到提审。

### 8.5 「开启 / 退出」类表述的方向判据

> **看这句提示的方向：是"增加限制"还是"减少限制"？增加限制的提示永远安全；减少限制的提示永远危险。**

| 表述 | 方向 | 判 |
|---|---|---|
| 「如本设备由未成年人使用，请**由监护人开启**未成年人模式」 | 增加限制 | **允许**（且主语必须是监护人） |
| 「监护验证后可切换模式」「退出未成年模式」 | 减少限制 | **禁** |
| 「本设备尚未开启未成年人保护，请开启」（陈述句） | 增加限制但否定框架 | **禁**（改用条件句：「**如**本设备由未成年人使用…」） |

**三条限定**：① 只允许出现在 `.unverified` 与设置一级常驻入口，**`.minorConfirmed` 内出现同类表述即判缺陷**（那里没有任何出口）；② 主语必须是监护人；③ 全文禁「关闭 / 退出 / 切换模式 / 输入验证码即可退出」，且不出现任何指向"如何解除"的表述。
**它是《指南》要求的入口可见性，不是解锁路标**——把"解锁路标"规则套到进入侧，等于为防一个不存在的风险，削掉监管要求的入口。

## 9. 验收清单

### 9.1 反向验收（出现即判不合格）

| # | 条件 |
|---|---|
| 1 | 某个能力只有彩蛋手势一条路（彩蛋承担主路径） |
| 2 | 关掉动效后某能力消失（只能减动画，不能减能力） |
| 3 | 关闭态出现中间帧 / 首末帧 diff ≠ 0 |
| 4 | 改名后宿主仍在原链路 |
| 5 | 玻璃浮层覆盖正文可见区（含"变暗"处理） |
| 6 | 非成年态出现联网能力，或宵禁样式缺失/多余 |
| 7 | 自绘浮层八项缺一（44pt 关闭按钮 / `accessibilityAction(.escape)` / 36×4pt 把手 / scrim 点击关闭 / 键盘避让 / VoiceOver 焦点陷阱 / Dynamic Type 溢出滚动 / 安全区适配） |
| 8 | 网络恢复且重试成功后，宵禁未即时解除 / 拦截页未当场消失 / 提示"请重新进入" |
| 8b | 宵禁拦截页使用 `backdrop-filter`（应为静态遮罩）/ 有任何淡入淡出（应 0ms 直切） |
| 8c | `.minorConfirmed` 内出现"开启 / 退出 / 切换模式"类表述，或 `.ageUnresolved` 横幅与拦截页文案不一致 |
| 8d | 原型出现字阶外字号（**.5 半像素值或字阶外整数档**）却未标注 `prototype-only`（**判定对象＝产品屏内**） |
| 9 | 关闭态描述不可断言（**"不可断言的描述等于没有描述"**：可断言的是"z0 与 z1 不创建"，不可断言的是"书脊不动"——书脊本来就不动时无法验证） |
| 10 | 三态文案硬编码在视图层，未从状态矩阵派生（改口径只改矩阵，不得两处维护） |
| 11 | 路径指引取不到系统本地化字符串时 fallback 到中文/英文（正确行为是整句隐藏——**"写错的路径比不写更糟"**） |
| 12 | `.unverified` 出现「在线功能不可用」类表述（B 版无任何在线功能可被禁用） |

**第 8d 条的读法（表外注，不改 12 条本身）**：8d 的括注已涵盖两档字号——「**.5 半像素值**」与「**字阶外整数档**」（如 12px）；8d 的判定对象是**产品屏内**（演示屏 `screen-stress`、调试坞等非产品界面不计入）。**但 8d 与 §1.7 的三条计数不是同一条**：§1.7 把**半像素值**与**字阶外字号**分列、各报各的数（第 1 条只数 `.5`，第 2 条单列整数档），8d 是把两者并起来做的**检查项**；**把它们合并成一条计数，就会得出"0 处违规"的假绿**。

**第 1 条的读法（表外注，不改 12 条本身）**：**实测**：「换一个版本」主路径 ＝ ④ 页底部阅读工具条按钮，**不触发本条**；**书摘卡**（EGG5）缺独立可达路径一事记在 §4.1 的留痕待办，**不属本条**——**本条查的是"主路径缺失"，§4.1 记的是"等价路径待补"，两件事不可合并**。**本条不再绑定任何具体功能**（改写理由：它是「反向验收」通则，守的是「别让某个能力只剩彩蛋一条路」；绑死在 EGG5 上，EGG5 一换语义这条就废；且原表述「只有彩蛋路径可达」在 D-41 之后**恒不触发**——「换一个版本」有工具条主路径，**一条恒不触发的反向验收项，看着像在守什么，实际什么都没守**）。

### 9.2 真机验收规定

玻璃观感**禁止**用模拟器截图终审；三档 tint 用**同屏并排 + 快速切换**两种方法判断（静态并排易受背景干扰，实际使用是同位置切换），**亮暗两底分别判**（同一 tint 在深底视觉权重更低）。两种方法都说"看不出"，才定为"没有差异"→ 并为两档。

POC-1：T1 首帧耗时 → 是否补 40ms 起步缓动｜POC-2：三档 tint 是否并为两档｜`GlassEffectContainer` spacing 真机校准值（单元素容器无作用）｜`.clear` 是否补档。

1. `.ageUnresolved` **套宵禁**——"保护已生效"写在界面上就不能没有时段管理；**保守方向出错是"少保护"，文案方向出错是"虚假陈述"，后者更重**。
